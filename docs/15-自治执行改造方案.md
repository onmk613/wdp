# 15 自治执行改造方案

> 状态：**P0–P2 已实施**（P0 地基修复 / P1 plan 一等产物 / P2 agent 自治执行）。本文是
> `wdp plan`、`wdp apply` 与自治执行的设计依据，代码中多处注释以 `docs/15 §x.y` 引用它：
> §1.1–§1.4 是 P0 回归项，§2.3 是编译期/执行期边界，§6.4 是 P1 验证，§7.1–§7.7 是 P2 实现。

## 背景与目标

`wdp run` 把编译与执行绑在同一个进程里（控制端加载 chart、算 values、逐任务远程执行，
`internal/cli/run.go:26`），三个结构性约束由此而来：**控制端耦合**（进程或链路一断，收敛停在
中途；跨网段还要求控制端能直连每台主机）、**执行前无可审计产物**（评审只能看 chart 与
inventory，"这台机器上会执行哪几条任务"没有可落盘、可 diff 的东西）、**不可复现**（同一份输入
编译出什么，没有内容寻址的答案）。方向是**把编译与执行拆开**：控制端离线编译出完全解析的 plan
（P1），执行可由控制端直接做，也可把分片交给目标机上的常驻 agent 自治收敛（P2）。

| 目标 | 含义 | 实现落点 |
|---|---|---|
| 断连容忍（G1） | agent 接受计划后控制端可随时断开 | `POST /plan` 异步：落盘、后台启动、立即返回 `run_id`（`internal/agent/apply.go:5`） |
| 中继可达（G3） | 跳板机 agent 即该网段的本地控制端 | 按 `via` 中继根分组提交分片（`internal/cli/applyauto.go:46`） |
| 平滑回退（G4） | 旧版 agent 无 `/plan` 端点时不中断交付 | `ErrPlanUnsupported` → 控制端直接执行（`internal/conn/agentc/plan.go:62`） |
| 可审计 | plan 是一等产物：可评审、可 diff、可执行 | `internal/cli/plan.go:3` |
| 确定性 | 同 chart + 同 values 两次编译逐字节相同 | `internal/plan/plan.go:7` |

关键取舍：**agent 不二次拉取 chart/inventory**。plan 内嵌 chart 树快照，执行现场不需要
chart 目录或 inventory 文件存在（`internal/cli/apply.go:3`）；制品不进 plan 本体（§3.4）。

## 2 编译期与执行期的边界

plan 是"跨主机信息已固化、单主机运行时信息保留"的快照（`internal/plan/plan.go:1`）。

### 2.1 编译期冻结

| 内容 | 说明 | 出处 |
|---|---|---|
| inventory 主机变量 | `h.Vars` 整体拷入变量域 | `internal/plan/compile.go:238` |
| 每主机生效 values | 全局 values 上应用 `inventory_override` 白名单后的结果 | `internal/plan/compile.go:220` |
| play vars | 静态最高层 | `internal/plan/compile.go:242` |
| fact cache | `--fact-cache` 指定的已有 facts 冻结进变量域 | `internal/plan/compile.go:95` |
| 内置变量快照 | `inventory_hostname`/`group_names`/`play_hosts`/`groups`/`hosts`/`hostvars` | `internal/plan/compile.go:250` |
| chart 树 | 文件快照（base64）、合并 helpers、chart.yaml 快照 | `internal/plan/compile.go:90` |
| play 编排属性 | become/become_user/serial/strategy/environment | `internal/plan/compile.go:201` |
| 任务清单 | `ResolvedTask` 树 + 主机内稳定 `idx` + 模块回滚能力分级 | `internal/plan/compile.go:342` |

### 2.2 执行期保留

| 内容 | 为什么不能在编译期定 | 出处 |
|---|---|---|
| `when`/`until`/`changed_when`/`failed_when` | 可能引用运行时 `register` | `internal/plan/plan.go:4` |
| `loop` | 同上 | `internal/plan/plan.go:132` |
| 模板渲染 | 值可能来自 `register`/facts | `internal/executor/planrun.go:11` |
| `register`/`set_fact`/`setup` 采集 | 本机运行时信息 | `internal/executor/planrun.go:10` |
| `play_batch`、`play_hosts` | 批次是执行期事实 | `internal/executor/builtins.go:52` |
| `playbook_dir` | 执行侧是物化目录，与编译端路径不同 | `internal/plan/compile.go:236` |
| `--tags`/`--skip-tags`、`--check`/`--diff` | 直接执行路径的执行选项（自治模式不支持，§9） | `internal/cli/apply.go:217` |

执行期只重新注入 `play_hosts`、`play_batch`、`playbook_dir`
（`internal/executor/builtins.go:52`），其余内置变量保留冻结值（`internal/executor/batch.go:87`）。

### 2.3 主机侧看不到其他主机的 facts

自治执行的位置可能在目标网段内的跳板机 agent 上（§7.4），那里既没有 inventory 文件，也拿不到
其他主机的 facts——所以 `groups`/`hosts`/`hostvars` 必须在编译期固化成字面值
（`internal/plan/plan.go:3`、`internal/executor/builtins.go:48`）。后果：**plan 模式下 `hostvars`
是编译期快照**，同一次 run 内其他主机 `set_fact` 的结果不会出现在里面；跨主机传播只有两条路
——编译期用 `--fact-cache` 冻结，或走 `wdp run` 路径（`internal/executor/batch.go:58`）。
主机自身的 facts 仍在本机求值并在批次间延续（`internal/executor/batch.go:85`）；`register` 不进
`hostvars`（`internal/executor/builtins.go:59`）。

## 3 plan 产物

### 3.1 顶层字段

`plan.json` 是一个 `plan.Plan`（`internal/plan/plan.go:44`）：

| JSON 字段 | 类型 | 含义 |
|---|---|---|
| `schema` | int | 结构版本，当前 `1`；不匹配时 `Load` 报错要求重编译（`internal/plan/plan.go:262`） |
| `plan_id` | string | 内容寻址 ID：`sha256(canonical(Plan))`，自身不参与计算 |
| `chart` / `version` | string | chart 名与版本 |
| `phase` | string | 生命周期相位（空串按 `deploy`，`internal/plan/compile.go:45`） |
| `wdp_version` | string | 编译端 wdp 版本（进 PlanID，见 §3.3） |
| `values` | object | 全局合并 values；**不含** `inventory_override`，每主机实际生效值在 `HostPlan.Values` |
| `meta` | object | chart.yaml 快照：marker 处置、相位属性、敏感键口径（`internal/plan/plan.go:53`） |
| `helpers` | string | `CollectHelpers` 合并结果（含子 chart），保证渲染可复现 |
| `files` | object | chart 树快照：相对路径 → base64 内容（仅小文件） |
| `payloads` | array | 超限/制品文件引用（路径 + 尺寸 + sha256），不进 plan 本体 |
| `hosts` | array | 每 `(play, host)` 一条 `HostPlan`；多 play 相位产生多批条目 |
| `relays` | object | `via` 中继根的连接元数据（中继机不一定是部署目标，其连接信息不在 `hosts` 里） |

`HostPlan` 是单主机在单个 play 中的分片（`internal/plan/plan.go:72`）：

| 字段 | 含义 |
|---|---|
| `play_idx` | 所属 play 序号；apply 侧据此重建 play 编排与批次 |
| `host` / `conn` | 主机名；`HostConn` 连接元数据（不含明文密钥，见 §3.5） |
| `values` | 该主机实际生效 values（已应用 `inventory_override`） |
| `vars` | 冻结变量域：inventory vars + values + play vars + 内置变量快照 + fact cache |
| `play` | play 级编排属性快照（name/hosts/become/serial/strategy/environment/vars） |
| `pre`/`tasks`/`post`/`handlers` | hook 拆分后的任务树；`idx` 在主机内连续且稳定 |

`ResolvedTask` 是 `model.Task` 的可序列化镜像，额外带计划专有字段：`idx`（journal 的键）、
`rollback`（模块声明的能力分级 full/partial/none/readonly）、`chart_ref`（执行侧按计划内
chart 树展开）；`when`/`loop`/模板原样保留（`internal/plan/plan.go:130`、
`internal/plan/compile.go:402`）。

### 3.2 PlanID 内容寻址

`ComputeID` 清空 `PlanID` 后 `json.Marshal` 再 sha256，`FillID` 幂等；`Write` 写临时文件 +
rename、权限 0600；`Load` 校验 schema 后重算摘要与文件中的 `plan_id` 比对，不一致即拒绝
（"file corrupted or edited"）；`Shard(hosts)` 只保留指定主机的分片、清空 `relays`、重算 PlanID
（同一分片重复提交幂等、续跑分片键稳定）；agent 收到提交后**再次**复核内容摘要
（`internal/plan/plan.go:216,233,252,175`、`internal/agent/apply.go:151`）。

### 3.3 确定性要求与它约束了什么

要求：同一 chart + 同一 values 两次编译产出**逐字节相同**的 `plan.json`
（`internal/plan/plan.go:7`，验证 `internal/plan/plan_test.go:90`）。为此：plan 不含时间戳字段；
JSON 键序由 `encoding/json` 对 map 的排序保证，chart 文件按相对路径排序后遍历；编译端版本
`wdp_version` 进 plan——换 wdp 版本必然换 PlanID；事实只能在编译期从 `--fact-cache` 读入，
部署相位编译**不连接主机**（`internal/plan/plan.go:8`、`internal/plan/compile.go:450,102,497`、
`internal/plan/plan_test.go:110`）。它约束三件事：`plan diff` 才有意义（顺序变化不算差异）、
golden 快照才可固定（`internal/plan/golden_test.go:3`）、分片 PlanID 才稳定（自治 `run_id` 由它
派生，§7.1）。

### 3.4 制品不进 plan 与 `--chart-dir`

单文件上限 `MaxFileBytes = 32MiB`、合计上限 `MaxTotalBytes = 256MiB`（`internal/plan/plan.go:33`）。
`snapshotFiles` 的规则：`packages/` 下任何文件（与体积无关）与超过单文件阈值的文件都记为
`PayloadRef{Path,Size,SHA256}` 而非嵌入；小文件合计超限即编译报错，提示把大负载移出 chart 用
artifact 模块按 URL 分发（`internal/plan/compile.go:426`）。理由：plan 是配置与意图的载体，不是
制品分发通道（`internal/plan/plan.go:63`）。补齐路径是 `wdp apply --chart-dir <chart目录>`：
`supplyPayloads` 逐条校验 sha256，**不一致即报错**（防止版本错配的制品被静默使用），文件缺失只
告警并让模块自行按 URL 获取（`internal/executor/planrun.go:106`）。

### 3.5 密钥脱敏

`hostConnOf` 提取可安全落盘的连接元数据（`internal/plan/compile.go:276`）：地址/端口/用户/
通道/TLS 材料/超时与 `via` 中继链保留（`internal/plan/compile.go:116`）；
`Password`/`KeyPassphrase`/`BecomePassword` **明文剔除**；
`PasswordEnv`/`KeyPassphraseEnv`/`BecomePasswordEnv` 保留；原值为 `env:VAR` 的
`Password`/`BecomePassword` 转写为 `PasswordEnvRef`/`BecomePasswordRef` 保留。执行侧
`HostConn.Host(name)` 还原为 `model.Host`，密钥在连接时经环境解析
（`internal/plan/compile.go:309`）。验证：`internal/plan/plan_test.go:256`。

## 4 逐 play 主机范围与变量域

### 4.1 一个 plan 的主机是逐 play 的

编译期**逐 play 选主机**：对每个 play 调 `inv.SelectPlays([]*model.Play{play}, limit)`，再为选中
的每台主机产出一条 `HostPlan`（`internal/plan/compile.go:111`）。多 play chart 的各个 play 往往
作用于不同主机组，`p.Hosts` 因此是 `(play, host)` 的扁平列表，同一台主机可以出现多次。

### 4.2 合成组与 `(playIdx, host)` 变量域

`RunPlan` 把计划内主机合成一份 inventory，并为每个 play 构造只含其成员主机的**合成组**
`__wdp_play_<playIdx>`（`internal/executor/planrun.go:180`）。`playsOf` 把扁平分片重建成 play
编排：同 `play_idx` 的分片合成一个 play（任务清单取首条代表分片），`pre/tasks/post` 按原
`Hook` 标记拼回主列表，`hosts` 取合成组名而不是 `all`（`internal/executor/planrun.go:133`）。
每主机 values 与冻结变量域的键是 `planScopeKey(playIdx, host) = "<playIdx>|<host>"`
（`internal/executor/planrun.go:184`）；命中时冻结变量域整体胜出，不再叠加运行期
inventory/values/play vars（`internal/executor/batch.go:30,64`）。

### 4.3 具体失败模式

两个缺陷都来自"plan 的 hosts 是逐 play 的"这一点，`internal/executor/planrun_test.go:1`
记录为历史缺陷：

| 缺陷 | 后果 |
|---|---|
| `playsOf` 把重建 play 的 `Hosts` 写成 `all` | 合成 inventory 是全 plan 主机的并集，多 play chart 的第二个 play 会作用到全部主机——安装任务下发到错误的节点 |
| 冻结变量域以主机名为键 | 同一主机出现在多个 play 时，后一个 play 的 play vars / `play_hosts` 快照覆盖前一个 |

修复即 §4.2。回归：`internal/executor/planrun_test.go:70`（主机范围）、`:93`（变量域）。

## 5 相位与 values

### 5.1 非部署相位的 values 来源（新语义）

非部署相位的 values 默认来自各主机 release marker 记录的实际部署 values，`-f/--set` 降级为对
marker values 的显式覆盖；marker 缺失或为 v1（无 values）时报错，**绝不静默回退**到 values.yaml
默认值——那会让卸载任务作用在错误路径上并报告成功（`internal/cli/markervalues.go:3`）。部署相位
编译全程不连接主机；从 marker 取 values 的相位必须先在控制端读 marker（`ValuesFromMarker` →
`resolveMarkerValues`，需连接），结果作为 `CompileOptions.HostValues` 传入，缺它时编译器直接
报错要求"先读 marker 再编译"（`internal/cli/plan.go:100`、`internal/plan/compile.go:81`）。
`wdp apply` 从计划内嵌的 chart 树按相位评估可逆性，`Destructive` 相位必经确认
（`internal/cli/apply.go:164`）；相位属性由 `planPhaseSpec` 从计划快照合成，与
`chart.PhaseSpecFor` 共用 `chart.MergePhaseSpec`（`internal/cli/apply.go:265`）；非 `--check`
且相位 `Records()` 时落部署记录、values 按 `sensitive_values` 脱敏（`internal/cli/apply.go:241`）。

### 5.5 验收

`internal/cli/phasevalues_test.go:3`：uninstall 的 values 默认从主机 marker 还原实际部署
入参——修复 §1.1 的"卸载静默空转并报告成功"；`internal/cli/plan_apply_test.go:106` 验证
plan + apply 路径同样删除真实部署目录。

## 6 P1 的命令面与验证

### 6.1 `wdp plan`

`wdp plan <chart目录|chart.tgz>` 编译计划：`--phase`（缺省 `deploy`）、`--limit`、`-f/--set`、
`--fact-cache` 与 `wdp run` 同语义，`-o/--output-file` 写 plan.json（0600）、缺省打印到 stdout
（`internal/cli/plan.go:62-67`）；写文件时 stderr 打印
`[plan] <path> written (plan_id=..., N host plan(s), M file(s))`（`internal/cli/plan.go:141`）。

### 6.2 `wdp apply`

执行 plan；连接元数据来自计划本身，现场不需要 chart 目录或 inventory 文件
（`internal/cli/apply.go:3`）。`--limit` 在计划主机范围内进一步收窄；`-t/--tags`、
`--skip-tags` 过滤任务；`--check`/`--diff` 预演（`--diff` 隐含 `--check`）；`-y` 跳过不可逆
确认；`--chart-dir` 提供大文件本地来源（§3.4）；`--fact-cache` 跨运行持久化 facts；
`--autonomous` 提交 agent 自治执行（仅 agent 通道）；`--detach`、`--resume`、
`--become-password-env` 为自治专用，脱离 `--autonomous` 时显式报错（此前被静默丢弃，
`internal/cli/apply.go:140`）。

### 6.3 `plan show` / `plan diff`

handler 分组，block/rescue/always 缩进，标注回滚能力），`--host` 只看某台主机
（`internal/cli/planview.go:19`）。`diff` 对比 chart 名/版本、相位、全局 values 字段级差异、主机
集合增删与逐主机任务增删；任务按 `idx+label+module` 对齐，**顺序变化不算差异**（`internal/cli/planview.go:104`）。

## 7 自治执行

### 7.1 提交与轮询

控制端按分组切分片（`plan.Shard`）POST 给根主机上的 agent（`internal/cli/applyauto.go:145`）：
`run_id = sha256(shard.PlanID + ":" + 根主机名)` 的前 16 位十六进制，由内容与根确定性派生
（`internal/cli/applyauto.go:104`）；请求体 gzip 压缩，agent 侧按 512MiB 上限解压读取
（`internal/conn/agentc/plan.go:64`、`internal/agent/apply.go:33`），立即返回 `run_id`、`state`
与各主机已跳过任务数 `ResumedFromIdx`（`internal/agent/apply.go:48`）。未 `--detach` 时每 2s
轮询 `GET /plan/status?run_id=&since_seq=`（单次 15s 超时，按 `seq` 游标只拉增量），轮询失败
只告警重试、**不影响主机侧收敛**（G1，`internal/cli/applyauto.go:204,225`）；`--detach` 接受
即返回，事后用 `wdp apply status <plan.json> <run-id>` 回查（重算各分组 `run_id`、支持前缀
匹配，找不到时提示重编译会得到新 id，`internal/cli/applyauto.go:173,278`）；
`POST /plan/cancel` 请求中止（`internal/conn/agentc/plan.go:137`）。

### 7.2 本机执行与 become

agent 把分片中 `local_host` 的主机条目改写成 `selfexec` 连接，其余主机按各自连接元类型远程
执行——同一个 `RunPlan` 调用天然覆盖直连与网段中继（`internal/agent/apply.go:302`）。
`selfexec` 与 `conn/local` 的区别是本包存在的全部理由：`local` 面向控制机演练、显式忽略
become 并告警；`selfexec` 面向自治执行，become 静默以 agent 自身用户执行比失败更危险，必须
真正提权（`internal/conn/selfexec/selfexec.go:5`）。提权语义与 HTTP `/exec` 共用
`selfrun.RunScript` 一份实现（`internal/selfrun/become.go:1`）；become 密码随分片一次性下发、
仅驻留内存、不落盘（`internal/agent/apply.go:37`）。

### 7.3 journal 与断点续跑

journal 是自治执行的进度载体：每行一条 JSON（字段 `seq`/`host`/`idx`/`label`/`state`/
`changed`/`msg`/`at`，`state` 取 `ok`/`changed`/`failed`/`skipped`/`unreachable`/`ignored`）、
追加写 + 每条 fsync（断电安全），`seq` 全 run 递增并在重启后从既有最大值续写
（`internal/agent/journal.go:3`）。`ReadJournal(path, sinceSeq)` 只返回 `seq > sinceSeq` 的
记录，中间坏行跳过而不抹掉前后有效记录（`internal/agent/journal.go:90`）。`CompletedIdx` 重放
journal 得到"主机 → 已完成任务序号集合"：只有 `ok`/`changed`/显式 `ignored` 算完成，
`failed`/`skipped` 不算——续跑要重做它们（`internal/agent/journal.go:116`）。`--resume` 时 agent
比对 run 目录里的 `plan.id`，不一致 409 拒绝（"旧进度对新 plan 无意义"）；一致则重放得到
`skipDone`，命中的 `(host, idx)` 按 `skipped` 记账、不执行（`internal/agent/apply.go:193`、
`internal/executor/task.go:29`）。**幂等不能替代续跑**：重跑意味着重做全部远程探测、金丝雀/
健康门语义被重置（`internal/agent/journal.go:4`、`internal/executor/executor.go:57`）；被跳过
的任务若声明了 `register`，只能用 skipped 结果占位——崩溃前的真实输出不可恢复
（`internal/executor/task.go:29`）。

### 7.4 `via` 中继分组

`via` 是组/主机变量（`via: <主机名>`），声明"这台主机经它可达"，链式可嵌套；加载期
`ValidateVia` 拦截未知名与成环（`internal/inventory/via.go:3,53`）。编译期把完整中继链写进
`HostConn.Via`（从第一跳到根，`internal/plan/compile.go:116`）；中继根的连接元数据单独记在
`Plan.Relays`——中继机不一定是部署目标（`internal/plan/compile.go:143`）。`groupByRoot` 按链
的最后一个元素（根）分组，无 `via` 的主机自成一组、根即自身，根缺少连接元数据时报错要求把
中继机加入 inventory 后重编译（`internal/cli/applyauto.go:45`）；分片清空 `relays`
（`internal/plan/plan.go:187`）。

### 7.5 常驻性与通道约束

自治执行需要常驻进程承载后台收敛，因此**仅支持 agent 通道**：根主机连接不是 `agent` 时提交前
显式报错并说明原因，不静默降级（`internal/cli/applyauto.go:142`，回归
`internal/cli/applyauto_test.go:91`）。`POST /plan` 的后台收敛使用独立于 HTTP 请求的 context，
控制端断开不影响执行（G1，`internal/agent/apply.go:229`）；收敛期间 `planActive` 置位，空闲
看门狗不判空闲——后台执行没有请求到达，agent 不能因为自己空闲而自杀
（`internal/agent/apply.go:234`、`internal/agent/server.go:248`，回归
`internal/agent/apply_test.go:339`）。

### 7.6 旧版 agent 回退

`POST /plan` 返回 404 时客户端返回 `ErrPlanUnsupported`，控制端打印说明并把该组转为本控制端
直接执行（`internal/conn/agentc/plan.go:60`、`internal/cli/applyauto.go:163,250`）。代价是这些
主机失去断连容忍。

### 7.7 幂等与并发

`planManager` 的键是 `run_id` 与 `plan_id`（`internal/agent/apply.go:81`）：

| 情形 | 处置 |
|---|---|
| 同一 `plan_id` 换 `run_id` 重复提交 | 幂等命中既有 run，不启动第二个收敛 |
| 同一 `run_id` 属于别的 `plan_id` | 拒绝（409） |
| 同一 `run_id` + 同一 `plan_id` | 幂等命中，返回当前状态 |
| 已有 run 在 `running` | 拒绝（"journal 即租约"，并发 run 互相踩踏比排队更危险） |

run 目录布局（`<runs_root>/<run_id>/`，默认根 `/var/lib/wdp/runs`，目录 0700）：`plan.json`
（0600）、`plan.id`、`journal.ndjson`（0600）、`state`（原子写，`running|done|failed|cancelled`）
（`internal/agent/journal.go:139`、`internal/agent/apply.go:177`）。进程重启后内存幂等表为空，但
`state` 与 journal 仍在磁盘上，`GET /plan/status` 会从落盘状态回答历史 run（`internal/agent/apply.go:342`）。

| 面 | 机制 | 出处 |
|---|---|---|
| 通道认证 | 对外（非回环）监听且未配置 mTLS 时拒绝启动（除非显式 `--allow-no-auth`）；mTLS 模式下校验客户端证书指纹在准许名单内（`/health` 放行） | `internal/agent/server.go:278,158` |
| `run_id` 注入 | `run_id` 直接拼进运行目录路径，提交与查询两条路径都按 `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$` 校验，不做"清洗"；`shortID` 对短于 12 位的取值原样返回，避免请求体可控时切片 panic | `internal/agent/request.go:17,27`、`internal/agent/apply.go:145` |
| 计划完整性 | 提交时重算内容摘要与 `plan_id` 比对，不一致 400 | `internal/agent/apply.go:151` |
| 自更新拒绝 | plan 若在参数里出现 agent 自身二进制路径，或以 `systemd_unit` 操作 agent 单元（缺省 `wdp-agent`），拒绝执行——否则会杀掉正在执行本 plan 的进程 | `internal/agent/apply.go:156` |
| 密码与落盘 | `BecomePassword` 仅随分片下发、驻留 agent 内存；plan.json 0600、run 目录 0700、journal 0600、物化文件 0600 | `internal/agent/apply.go:37,177`、`internal/plan/plan.go:271` |
| 路径越界 | 物化时拒绝 `..` 前缀与绝对路径 | `internal/plan/plan.go:292` |

## 9 已知限制

1. **自治模式不支持 `--tags`/`--skip-tags`**：提交的是编译期固化的任务清单，agent 侧没有过滤
   能力，静默忽略会让用户以为只跑了部分任务（`internal/cli/applyauto.go:116`）。
2. **自治模式不支持 `--check`**（`--diff` 隐含 `--check`，同样被拒，`internal/cli/applyauto.go:113`）。
3. **非 agent 通道不支持自治执行**（§7.5）；**旧版 agent 回退后失去断连容忍**（§7.6）。
4. **journal 只按 `(host, idx)` 记账**：失败任务的部分副作用不可追踪；续跑重做
   `failed`/`skipped`，被跳过的 `register` 任务只能用占位结果（§7.3）。
5. **续跑要求 plan 未变**：`plan.id` 不一致即拒绝，需换新 `run_id`（§7.3）。
6. **同一 plan + 同一根在 agent 存活期间只收敛一次**：重复提交幂等返回既有 run；重启后幂等表
   为空，同一 `run_id` 会重跑（需 `--resume`）（§7.7）。
7. **自治模式不支持 `--chart-dir`**：制品补齐发生在控制端的 `RunPlan`（`PayloadDir` 非空时），
   agent 侧执行器不设置它；plan 含 payload 且显式传 `--chart-dir` 时在提交前直接报错，
   不再等到收敛中途才失败（`internal/cli/applyauto.go:121`、`internal/executor/planrun.go:108`）。
   制品需先分发到目标 agent，或改用不带 `--autonomous` 的 `wdp apply`。
8. **plan 模式下 `hostvars` 是编译期快照**：其他主机的 `set_fact` 不会出现在里面（§2.3）。
9. **`wdp apply status --limit`** 与提交侧同口径：只查询命中该模式的主机所在的 relay 分组；
   模式未命中任何 plan 主机时报错（`internal/cli/applyauto.go:279`）。

## 10 与 `wdp run` 的关系

`wdp run` 是"编译 + 执行一条龙"：一个进程里加载 chart、算 values、直接驱动执行器
（`internal/cli/run.go:26`）。`plan` + `apply` 把这两步拆成产物与执行，因此 `run` 语义上等于
`plan` + `apply` 的组合（`docs/12-cli命令参考.md`）。代码层面的等价性来自**共用
`runTaskOnHost` 以下的全部代码**：两条路径都经 `Executor.Run` → `runPlay` → `runBatch` →
`runTaskOnHost`，模块执行、when/loop、register/notify/handlers、check/diff、批次策略只有一份
实现，语义零漂移（`internal/executor/planrun.go:3`、`internal/executor/task.go:19`）。

| | `wdp run` | `wdp plan` + `wdp apply` |
|---|---|---|
| 跨主机信息 | 运行期 inventory 计算 | 编译期冻结值（`HostPlan.Vars`） |
| chart 树 | 现场 chart 目录 | 计划内嵌快照，物化后 `chart.Load` |
| 执行位置 | 控制端 | 控制端，或目标 agent（`--autonomous`，断连容忍） |

`run` 路径**不经过 plan 产物**（不调用 `plan.Compile`/`plan.Load`），而是直接驱动同一执行器；
等价性由 `internal/cli/plan_apply_test.go:38` 固定：同一 chart、同一入参下两条路径的落盘效果与
marker 内容一致。
