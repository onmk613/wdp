## 2. 总体评价

### 2.1 做得好的地方（有证据，不是客套）

**架构**
- 三条设计铁律**经实测成立** ✅：`model` 零内部依赖；`module` 只 import
  `conn/model/render/shellquote`；`conn` 层不依赖 `config`（默认值经
  `conn.Defaults` 显式注入）。这类"写在文档里的不变量"能扛住代码演进，很少见。
- 组合根（`cli`）与领域层分离干净：`config.Current()` 的 39 处调用里 38 处在 `cli`，
  唯一在 `inventory` 的还是显式传参（`buildHost(..., cfg *config.Config)`，nil = 内置默认）✅。
- 通道抽象（`conn.Conn` 5 个方法）稳定，`NativeExtractor` 用可选能力接口做渐进增强，
  没有把 agent 特性泄漏进模块。

**安全设计（多数同类项目做不到）**
- 登录：强制 JSON Content-Type（跨站表单带不了）+ `SameSite=Strict` + HttpOnly +
  条件 Secure + bcrypt + 失败锁定 + 账号存在性统一口径（不枚举）。
- 会话：256-bit `crypto/rand` token、滑动 2h + 绝对 12h 双 TTL、按用户批量吊销、
  周期清扫、`kill` 前缀多命中时**拒绝**而非"踢第一个"。
- 反向代理：`X-Forwarded-*` **仅在 trusted-proxy CIDR 命中时**采信（`remoteIP` /
  `requestIsHTTPS` 各自独立判定）✅。
- agent 侧：mTLS `RequireAndVerifyClientCert`；`run_id` 正则防路径穿越；
  解压的 zip-slip / 符号链接 / 硬链接 / 解压炸弹防护完整（`archive.go:safeLinkTarget`
  写得比 `chart/tgz.go` 还严谨）；become 密码走 stdin 不进 argv。
- plan：内容寻址 `PlanID` 且 agent 侧**重算校验**（`apply.go:100`）；schema 版本校验。

**工程纪律**
- CI 门禁覆盖：build / vet / gofmt / tidy 差异 / `-race` / 覆盖率 ≥60% / golangci-lint /
  4 平台交叉编译矩阵 / `GOEXPERIMENT=jsonv2` 观察位 / `govulncheck`（版本锁定）。
- 文档与代码同源：`wdp module <name>` 打印的参数文档来自模块自身 `Params()`。
- 注释解释"为什么"而非"是什么"（回滚为何用独立 ctx、为何 `WriteTimeout=0`、
  为何指纹校验放在脚本里——即使个别结论有问题，这个习惯本身很有价值）。

### 2.2 主要短板

| 类别 | 一句话 |
|---|---|
| **安全** | 有 5 个必须立刻修的问题，其中 1 个可直接导致服务端任意文件读取（→ 根 CA 私钥） |
| **可用性** | 实时推送（SSE）在生产**恒定 500**，且测试因接线分叉测不出来 ✅ |

## 3. 问题清单

### 3.1 严重（P0：建议一周内修完）

#### P0-1 chart tgz 符号链接绝对路径逃逸 → 服务端任意文件读取 ✅

`internal/chart/tgz.go:69`

```go
rel := strings.TrimPrefix(filepath.ToSlash(hdr.Linkname), "/")
```

`TrimPrefix` 只剥**一个**前导斜杠：归档里写 `Linkname = "//etc/passwd"` →
`rel = "/etc/passwd"` → `os.Symlink("/etc/passwd", target)` 在解包目录内建出
**指向归档外**的绝对链接（`..` 检查因此失效，注释却写着"绝对目标收敛为 tmp 内相对写法"）。

利用链（只需 operator 级权限）：
1. 构造 tgz：合法 `chart.yaml`/`values.yaml` + 一个 symlink 条目 `app/leak -> //etc/passwd`；
2. `POST /api/apps/upload` → `chartMetaOf` 加载成功即入库；
3. `GET /api/apps/{id}/spec` → `console.ReadSpecFromDir`（`console/spec.go:149`）
   对非目录项 `os.ReadFile(path)` **跟随链接**，≤512 KiB 且 UTF-8 合法即原文回传 ✅。

可读到 `/proc/self/environ`（`--admin-pass-env` 部署下 = 管理员口令明文）、
`/proc/self/cmdline`（→ `--data` 路径）→ `<data>/ca/ca.key`（**根 CA 私钥**）。
`console/chartfs.go` 的 `CopyDir` 同样跟随链接，还能把内容**写进新版本制品并可下载**。

**修复**：直接复用 `internal/agent/archive.go:195 safeLinkTarget` 的判定
（`HasPrefix(link,"/")` 一律拒绝），并在 `spec.go`/`chartfs.go` 只处理
`d.Type().IsRegular()`。

#### P0-2 纳管引导链路可被中间人整体替换，token 可直接兑换逐主机私钥 ✅

- 一键命令走**明文 HTTP**：`internal/web/enroll.go:298`
  `curl -fsSL %s/enroll/%s/script.sh | sudo sh`，`advertiseBase` 默认
  `scheme = "http"`（`:320-324`，仅 `r.TLS != nil` 才 https）。
- 脚本里的 `CA_FP` 校验（`:215-217`）与脚本**同源同通道**，对主动 MITM 零价值 ✅。
- `/enroll/*` 全部无会话鉴权（`:254-263`），token 在 **URL path** 里（进反代/网关日志、
  shell 历史）；`GET /enroll/{token}/host-key` 直接下发 **server 侧保存的逐主机私钥**
  （`<caDir>/hosts/<name>.key`，`:429-433`），且这一步不消费 token、不绑定来源 IP ✅。

后果：无需任何凭据即可拿到目标机 root（替换脚本）或全网 agent 私钥 +
任意 SAN 的 CA 签发证书。**这是当前信任链唯一的锚点，而锚点可被替换。**

**修复（按性价比排序）**：
1. 私钥**改由目标机本地生成**（agent 二进制已在目标机落地，可跑 `genkey`/CSR 子命令），
   server 端不再持有 agent 私钥 —— 一次性消除"私钥集中托管"这个结构性弱点；
2. enroll 端点仅在 HTTPS 或回环上暴露（`--addr` 非回环且无 `--tls-cert` 时拒绝启动）；
3. 下发二进制附 `bin/SHA256SUMS` 并在脚本内校验；token 一次性消费 + 绑定来源 IP。

#### P0-3 控制台 → agent 只验链不验身份，且静默回退明文 ✅

- `internal/web/enroll.go:125` `InsecureSkipVerify: true` + `:171`
  `TLSSkipHostVerify = true`：**任何本 CA 签发的证书都被当作任意主机**。
  而纳管签发的 SAN 本来**就含纳管地址与主机名**（`:448-457`），
  CLI 路径（`conn/agentc/tls.go:27-39`）反而会设 `ServerName` —— 只有控制台自举路径关掉了。
- `internal/worker/probe.go:51-59`：https 探测失败**无条件回退 http**；
  `internal/web/monitor.go:55-63`：`agentScheme` 探不通直接返回 `"http"`。
  执行/下发 plan/升级二进制全部据此选通道（`exec.go:231`、`apps_run.go:268`、
  `upgrade.go:144`）。

后果：任一台 agent 沦陷（或拿到 `hosts/*.key`）即可冒充**任意其它主机**，
截获含 `become_password` 的 plan、伪造 exec/facts、替换 agent 二进制；
MITM 只需阻断 TLS 即可触发无告警的明文降级。

**修复**：删除 `TLSSkipHostVerify`（改为按台账 `Address` 校验证书 SAN）；
已纳管主机禁止回退明文，确需明文用显式开关 + 审计告警。

#### P0-4 SSE `/api/runs/stream` 在生产恒定 500（测试接线分叉掩盖）✅

```go
// observability.go:62-73
type statusWriter struct { http.ResponseWriter; code int; wroteHdr bool }
// ← 没有 Flush()，嵌入的接口也没声明 Flush，方法集不含 Flush
// server.go:242
Handler: s.metricsMiddleware(s.mux)   // 生产：包了中间件
// server.go:226
func (s *Server) Handler() http.Handler { return s.mux }  // 测试：裸 mux
// runevents.go:64
fl, ok := w.(http.Flusher); if !ok { 500 "streaming unsupported" }
```

生产路径上 `w` 是 `*statusWriter`（无 `Flush`）→ 断言必然失败 → 500；
所有测试走 `s.Handler()`（`web_test.go`、`runevents_test.go:56`）绕过中间件，
所以 CI 全绿 ✅。前端 `api.ts:406-413` 的 EventSource 无 `onerror`/退避，
浏览器每 ~3s 重连拿 500，实时推送功能全废并退回全量轮询。

**修复**：给 `statusWriter` 加 `Flush()`（或 `http.NewResponseController`）；
并把 SSE 测试改成经过 `metricsMiddleware` —— 后者才是防复发的关键。

#### P0-5 多处无上限读取 → 单条任务可打挂控制台 ○（关键点已复核 ✅）

| 位置 | 问题 |
|---|---|
| `internal/module/archive.go:45` | `selectArchiveMembers` 对每个成员 `io.ReadAll`，**无上限** ✅ |
| `internal/module/unarchive.go:208` | members 路径 `os.ReadFile` **绕过** `readLocalSrc` 的 `max_upload_mb` ✅ |

## 4. 优化建议（性能与架构）

### 4.1 前端首屏：5.1 MB → ~1.2 MB（性价比最高的一条）✅

**实测**（当前 `frontend/dist`）：

```
monaco-Big9nSam.js   raw 3.7M   gzip 965K   ← Chart IDE / playbook 编辑器才需要
element-CAo_-WJT.js  raw 992K   gzip 323K
index-CgWUTpQq.js    raw 376K   gzip 122K
yaml.worker          raw 698K
+ 480 KB CSS，全部 **未压缩**（服务端无 Content-Encoding）
```

`frontend/dist/index.html` 对 monaco 与 element 都有 `<link rel="modulepreload">`：
**登录页也要拉 5.1 MB JS**。三条改动：

1. **路由懒加载**：`router.ts` 里 14 个视图全部静态 import → 改 `() => import(...)`；
   monaco 只在 `AppIDE`/`PlaybookPage` 内动态 `import()`。
2. **构建期预压缩**：`vite-plugin-compression` 产出 `.gz`/`.br`，`build.sh` 一并
   `cp -R` 进 `static/`。
3. **服务端按 `Accept-Encoding` 送预压缩文件**：`handleAssets` 加一层
   （Vary: Accept-Encoding + 命中 `.br`/`.gz` 则设 `Content-Encoding`），
   零依赖、零运行时开销。

预期：首屏 JS 从 5.1 MB（未压缩）降到约 1.4 MB（gzip 后 ≈450 KB），
IDE 页才付 monaco 的代价。

### 4.2 产物瘦身：agent 不需要控制台

`bin/wdp-*` 既当 server 又当 agent，每个目标机都被推一份**含 6.7 MB 控制台资源**
的 25 MB 二进制。用 build tag（`//go:build !noconsole`）拆出 `wdp-agent` 变体，
下发体积可降 ≈25–30%。对"纳管上千台 + 反复升级"的场景收益可观。

### 4.3 数据层

```sql
-- 迁移追加（当前 runs/run_tasks 零索引）
CREATE INDEX idx_run_tasks_run  ON run_tasks(run_id);
CREATE INDEX idx_run_tasks_host ON run_tasks(host, id);
CREATE INDEX idx_runs_status    ON runs(status, app_id);
```
外加：读路径改 `QueryContext` + 超时（单连接下这是唯一的排队兜底）；
给 `runs/run_tasks/audit_logs` 加保留窗口（复用 `metrics_5m` 的 prune 循环）；
`DeleteHost` 同事务清 `host_alerts`/`metrics_5m`；
`app_drafts` 加 TTL；`schema_version` 改 `SELECT MAX(version)`；
Open 后对 `wdp.db*` 显式 `chmod 0600`。

### 4.4 确定性与可测性

- `fanOut` 结果按 `runs` 下标写入（而非完成顺序），子 chart handler 用
  `sortedSubNames` 排序 —— 让 golden/plan diff/CI 日志可比对。
- SSE 与其他中间件敏感端点：**测试必须走生产接线**。建议 `Handler()` 直接返回
  `metricsMiddleware(s.mux)`，另开 `muxOnly()` 给需要绕过中间件的用例。
- 补 fuzz（Go 原生，零成本）：`playbook.Parse`、`chart` tgz 解包、
  `plan.Load`、agent `/plan` 解码、`render` 模板 —— 这几个都是不可信输入入口。
- 补 `t.Parallel()`（当前 0 处，`internal/web` 一套 80s 串行）；
  给 `plan.Compile` 与 `executor.fanOut` 加 benchmark，让性能有回归信号。

### 4.5 架构收尾

- **完成 `web → console → store` 迁移**（现 20/33 文件直接依赖 store）：
  `internal/web` 已 10,974 行、是全项目最大包，继续长会把传输层和领域逻辑焊死。
- **统一错误翻译层**：现在既有 `writeInternal` 脱敏口径，又有 10+ 处 `err.Error()` 直出；
  建议 handler 只返回"已翻译错误 or 未翻译错误"，由 `httpx` 统一决定 500 文案。
- **给 agent 加授权分层**：目前"认证通过 = root"且全网共用一张 `ctl` 证书。
  最小改进是把 `ctl` 换成逐控制端证书 + 端点白名单（至少 `/shutdown`、`/file` PUT
  与 `/exec` 分开授权），并在安装单元里写死 `--pin-client-fp` 作为可撤销点。
- **`Conn` 增加提权写路径**（见 P1-2）：`UploadFile` 带 `BecomeUser`，
  sshc 走"临时文件 + `sudo mv`"，agent 侧透传。
