# 04 连接与认证

四种连接通道（inventory 主机条目的 `conn` 键选择）。所有内置模块在**控制端**实现、只依赖 exec/upload/download 三个原语，因此各通道行为完全一致。

连接参数（`conn`、`user`、`port`、`key_path` 等）可在三个层级配置，高 → 低依次覆盖：

1. **主机条目**：`web1: {conn: push, port: 2222}`
2. **组级 vars**（含 `all.vars` 与 children 展开，同变量域合并顺序）：
   ```yaml
   all:
     vars:
       conn: push    # 全 fleet 默认 push 通道
       user: root    # 注意键名是 user（不是 ssh_user）
   ```
3. **wdp.cfg**：`[run].conn`（默认连接类型）与 `[ssh]`（`user`/`connect_timeout`/`host_key_check`/`known_hosts`）；仍未给出的 `user`/`port`/身份文件由 `~/.ssh/config` 补全（见下文）

连接参数键是保留键：出现在组 vars 或主机条目时成为连接参数而**不进入模板变量域**——应用变量请避开这些键名（如用 `nginx_port` 而非 `port`）。

## 通道总览

| conn | 场景 | 目标机要求 |
|---|---|---|
| `ssh`（默认） | 通用 | POSIX sh（推荐开 SFTP；无 SFTP 自动降级 exec 流式） |
| `agent` | 长期纳管、高频操作 | 常驻 `wdp agent` 进程 |
| `push` | 一次性批量操作想获得 agent 速度 | 同 ssh + 与控制端同平台二进制 |
| `local` | 演练 / CI / 管理本机 | 无（注意：**local 通道忽略 become，不提权**） |

## SSH 通道

认证链（依次尝试）：

1. 身份文件：inventory 显式 `key_path`，未显式时用 `~/.ssh/config` 匹配块的 `IdentityFile`（见下节）。每个身份文件自动附带**伴随证书**（`<私钥>-cert.pub`，OpenSSH 约定）——服务器只信任 CA 签发证书（裸公钥不在 authorized_keys）时由此认证，与交互 ssh 行为一致。私钥口令用 `key_passphrase` / `key_passphrase_env`
2. ssh-agent
3. 默认密钥（~/.ssh/id_ed25519、id_ecdsa、id_rsa；已从 ssh config 取得身份文件时不再追加，对齐 OpenSSH）
4. 密码认证 `password` / `password_env`（含 keyboard-interactive）

```yaml
webservers:
  hosts:
    web1: {host: 10.0.0.11}                                      # 密钥直连
    web2: {host: 10.0.0.12, key_passphrase_env: KEY_PW}          # 带口令私钥
    web3: {host: 10.0.0.13, password_env: SSH_PW, port: 2222}    # 密码认证
```

### ~/.ssh/config 集成

wdp 解析 `~/.ssh/config`（OpenSSH 首匹配语义），为 inventory 中**未显式指定**的连接参数补全，使"交互 ssh 能通、wdp 不通"的环境差异消失：

- `User` / `Port`：取文件顺序中第一个匹配 Host 块的值
- `IdentityFile`：跨全部匹配块按序累积（多个密钥依次尝试）

优先级：inventory 主机条目显式键 > `~/.ssh/config` > `wdp.cfg [ssh]` 默认值 / 内置默认（对齐 OpenSSH 的 命令行 > 用户配置 > 内置默认）。

匹配语义：`Host` 模式支持 `*` / `?` 通配与 `!` 取反，匹配对象为 inventory 主机名与连接地址（任一命中即算匹配）；`Include` 原地展开（glob、`~` 展开、相对路径按包含文件目录解释）；`Match` 块不求值（跳过）。

环境变量 `WDP_SSH_CONFIG` 可覆盖配置文件路径（设为 `none` 显式禁用），排查连接问题时可临时禁用以对比行为。

### 主机指纹校验

`host_key_check` 默认**开启**（安全默认）。新主机首次连接前采集指纹：

```sh
wdp scan-ssh webservers -i prod.yaml                # 采集组内全部主机
wdp scan-ssh 'web*' -i prod.yaml                     # 支持选择模式语法
wdp scan-ssh web1 --known-hosts /path/known_hosts   # 指定指纹文件
```

明确接受风险时可对单台关闭：`web4: {host: 10.0.0.14, host_key_check: false}`。

**坏行容错**：known_hosts 中的损坏记录（截断、CRLF 混入 base64 等）不再拖垮
全部连接——加载时逐行解析，坏行跳过并向 stderr 告警（对齐 OpenSSH 行为）。
`scan-ssh` 自愈：加载时识别的坏行会在下次落盘时自动清除（告警带行内容，
便于定位成因）。

### 提权（become）

play 或任务级 `become: true` 后，远端命令经 `sudo` 执行（默认 root，`become_user` 可改）：

```yaml
- hosts: dbservers
  become: true          # play 级：全部任务提权
  tasks:
    - name: 不提权的例外
      shell: id
      become: false     # 任务级覆盖
```

免密 sudo 直接可用；需要密码时 `become_password` / `become_password_env`
（agent 通道经请求体传输、目标机侧密码经 stdin 传给 sudo，不落命令行；仍建议仅在启用 mTLS 的部署使用）。

## Agent 通道（常驻）

目标机启动常驻 agent，控制端 HTTP(S) 直连（免每任务 SSH 握手）：

```sh
# mTLS 模式（远程纳管的标准姿势，证书签发见下节）
ssh target 'wdp agent --listen 0.0.0.0:7602 --ca ca.crt --cert 10.0.0.13.crt --key 10.0.0.13.key &'
# 生产建议 systemd 托管（示例见 examples/wdp-agent.service）
```

安全默认：`wdp agent` **默认仅绑定回环地址**（127.0.0.1），对外（非回环）监听且
未配置 mTLS 时**拒绝启动**——agent 的 `/exec`、`/file` 是命令执行与文件读写
原语，无认证对外监听等于暴露 RCE。可信内网可显式 `--allow-no-auth` 放行。

inventory（`ca_file`+`cert_file`+`key_file` 为控制端侧 mTLS 三件套）：

```yaml
web1: {conn: agent, host: 10.0.0.13, agent_port: 7602, ca_file: ./ca/ca.crt, cert_file: ./ca/ctl.crt, key_file: ./ca/ctl.key}
web2: {conn: agent, agent_url: 'https://10.0.0.14:7602', ca_file: ./ca/ca.crt, cert_file: ./ca/ctl.crt, key_file: ./ca/ctl.key}
```

IPv6：`host` 填裸 IPv6 字面量即可（各通道自动处理）；手填 `agent_url` 时需按 URL 语法带方括号并加引号（`'https://[fd00::5]:7602'`）；zone ID（`fe80::1%eth0`）不支持。

`wdp agent` 完整参数见 [CLI 参考](12-cli命令参考.md#wdp-agent)。

## mTLS 模式（自建 CA）

适用于跨不可信网络管理 agent。

```sh
wdp ca init ./ca                             # 1. 建 CA（默认 1 天，PathLen=0，私钥明文 0600；--name 自定义文件名）
wdp ca issue ./ca --name 10.0.0.14 --san 10.0.0.14  # 2. agent 服务端证书（输出目录为位置参数；SAN 一律经 --san）
wdp ca issue ./ca --name ctl --profile client  # 3. 控制端客户端证书（输出 SHA256 指纹）
wdp ca init ./ca --days 365                  #    常驻 agent 机群：按需放宽 CA 窗口
```

**叶子有效期自动档**：`ca issue`/`ca renew` 不给 `--days` 时按签发 CA 剩余寿命就近取值——
CA 剩余 ≤30 天（如默认 1 天 CA）叶子**跟随 CA 一起到期**（短会话信任链不留尾巴）；
30~60 天取剩余的 50%（留续期窗口又不越界）；>60 天（长期 CA）上限 30 天。
显式 `--days` 不分段，但**一律不超过 CA 到期**（钳制）。

**自定义根证书**：`issue`/`renew` 的 `--ca-cert/--ca-key` 指向的是**根 CA（签发者）**
——用它给新证书签名，不是要生成的证书本身（新证书输出到 `<输出目录>/<name>.crt|.key`，输出目录为位置参数，缺省 `.`）。
默认取 `<dir>/ca.crt|ca.key`；指向 openssl 等自制的组织根 CA（明文 SEC1 EC /
PKCS8 私钥）即可复用既有信任链，无需任何导入步骤。校验：必须是 CA 证书、
未过期、与私钥匹配。

**短有效期取代静态加密**：CA 私钥不再做口令加密（PBKDF2/AES 信封已移除），
一律明文 0600、目录 0700。默认 1 天的 CA 是远程部署的短周期会话信任根，
泄漏窗口天然受限——静态加密所防的"密钥文件被拷走"威胁在一天的有效期面前
收益极小，而口令分发/注入本身又是新的泄漏面。常驻机群用 `--days` 放宽后，
依靠文件权限与专用控制节点隔离即可。

多地址主机（内外网双 IP、NAT、堡垒机端口转发）用 `--san` 一次覆盖全部可达地址，
无需为每个地址单独签证书、也无需按主机降级 `insecure_skip_verify`：

```sh
wdp ca issue ./ca --name 10.0.0.14 --san 10.0.0.14 --san 192.168.1.14 --san web1.internal
# renew 续期时 SAN 全量继承，无需重述
```

agent 端带证书与指纹准许名单启动：

```sh
ssh target 'wdp agent --listen 0.0.0.0:7602 --ca ca.crt --cert 10.0.0.14.crt \
    --key 10.0.0.14.key --pin-client-fp sha256:<ctl指纹> &'
```

inventory 端：

```yaml
web1:
  conn: agent
  host: 10.0.0.14
  agent_port: 7602
  tls: true
  ca_file: ca/ca.crt          # 不配则信任系统证书池（公网 CA 场景）
  cert_file: ca/ctl.crt
  key_file: ca/ctl.key
  # tls_server_name: other     # 一般无需填写：默认已按 host 字段（未填即主机名）校验；
                               # 仅当证书 SAN 是其它名称时显式指定
  # tls_skip_host_verify: true # 仅跳过主机名校验，保留 CA 链校验
```

控制端对 agent 服务端证书的校验强度（从强到弱）：

| 配置 | 链校验 | 主机名（SAN）校验 |
|---|---|---|
| 默认 | ✔（`ca_file` 或系统池） | ✔（证书 SAN 含 **host 字段 / inventory 主机名** 即可——端口转发、NAT 场景经 `agent_url` 连入时默认按逻辑身份而非入口地址校验） |
| `tls_server_name: <名称>` | ✔ | ✔（显式改按该名称） |
| `tls_skip_host_verify: true` | ✔ | ✘ |
| `insecure_skip_verify: true` | ✘ | ✘ |

所以给 agent 签证书时 `--name` 直接用 inventory 主机名或 `host` 字段值，
端口转发/NAT 入口地址与证书不一致也无需额外配置。

agent 端对控制端只做证书链校验（客户端证书无主机名概念），可再用 `--pin-client-fp`
钉住具体指纹实现精确吊销。

证书安全设计：

- **短周期 + 更新延期**：`wdp ca renew <证书路径> --days N` 原地延期（`--days` 为增量，字段全继承，旧件自动备份 `*.old.<时间戳>`）；`--new-key` 换钥即吊销旧证书
- **指纹准许名单（精确吊销）**：`--pin-client-fp` 可多次；撤权 = 删指纹重启 agent，

- **明确降级**：`tls_skip_host_verify`（保链跳名）/ `insecure_skip_verify`（全跳过），测试环境用
- 无 CRL/OCSP：吊销依赖指纹名单与短周期轮换

### 运维端点（mTLS 保护，常驻 agent 日常运维免 SSH）

| 端点 | 用途 |
|---|---|
| `GET /health` | 探活 + `cert_not_after`（服务端证书到期时刻）+ `idle_timeout_sec` / `idle_left_sec`，可批量巡检证书剩余有效期 |
| `POST /shutdown` | 优雅退出并自清理（无额外开关：无认证模式直接执行，mTLS 模式经客户端证书/pin 校验后执行）。请求体**空或空 JSON `{}`** 即默认清理（全部 best-effort，单项失败只记日志）：删除自身二进制、证书材料（cert/key/**含 CA**）、尝试停用 systemd 单元（默认 `wdp-agent`，`--systemd-unit` 按实际部署名指定；非 systemd 环境静默跳过）。也可传 JSON 指定清理项一并执行：`{"systemd_unit":"<单元名>","files":["/path/..."]}`（files 为文件或目录，根路径拒删防手滑）。`--cleanup-on-shutdown` 只影响**空闲超时退出**是否自清理，`/shutdown` 显式信号总是清理 |
| `GET /logs` | 拉取近期日志（内存环形缓冲，约最近 512KiB，text/plain）。与其它业务端点同认证；控制端 `wdp agentctl logs` 逐主机拉取落盘。完整历史走 `--log-file` 落盘后经 `GET /file` 拉取 |

### 运行日志（slog）

agent 内置 slog 日志内核，扇出到三个目的地：**stderr**（始终，systemd 托管时进 journal）、**`--log-file <路径>`**（可选，追加写、自动建父目录、0600；**自清理不删除该文件**——退役后保留供审计，确要删须显式列入 `/shutdown` 的 `files`）、**内存环形缓冲**（始终，约 512KiB，`GET /logs` / `agentctl logs` 拉取）。

级别由 `--log-level` 控制（默认 `info`）：

| 级别 | 内容 |
|---|---|
| `info`（默认） | 必要运行记录：执行的命令（超长截断）、上传/下载的文件与字节数、解压 src→dest 与文件数、换证与到期时间、收到关闭信号、自清理动作、空闲退出 |
| `debug` | info 之上记录**每一次操作**的完整细节：命令的 user/cwd/超时/环境变量数/退出码/输出量、逐请求访问日志（方法/路径/状态/耗时，仅已认证请求；`/health` 探测不记） |
| `trace` | debug 之上对每个请求/响应做 **httpdump**（头全量、体截断至 4KiB，`become_password`/私钥等敏感字段值一律遮蔽 `***`） |
| `warn` / `error` | 仅告警与错误（清理失败、换证被拒等） |

控制端汇集：`wdp agentctl logs <主机模式>` 拉取所有匹配 agent 的近期日志，逐主机写入 `--out` 目录（默认 `./wdp-agent-logs/<host>.log`），即"agent 日志传输到控制端、用文件记录"。

证书到期巡检：`wdp agentctl status` 批量查看 `cert_not_after` 剩余天数。
远程热换证书的方案（CSR 模式等）规划中；现阶段更换证书 = `wdp ca issue`
重签后 scp 到目标机重启 agent。

**吊销泄漏的客户端证书规程**：移除 `--pin-client-fp` 中的指纹并重启目标
agent 即生效（存量连接随重启断开）。

敏感操作（远程换证、远程清理、空闲自动退出）均输出事件日志（见"运行日志"小节），
systemd 托管时进 journal 可追溯。

## Push 通道（临时 agent）

SSH 自举一个临时 agent，获得 agent 的执行速度、用完自删：

```yaml
web1: {conn: push, host: 10.0.0.12, user: root}          # 默认端口 7602，占用自动换端口
web2: {conn: push, host: 10.0.0.13, agent_port: 7700}    # 指定起始端口
```

流程：上传控制端自身二进制 + 会话级 mTLS 三件套 → 远端以 `--ca/--cert/--key` 启动（无 token，客户端证书即凭证）→ 控制端 HTTPS 直连（只验证书链不验主机名）→ 结束自删二进制与证书文件（`keep_agent: true` 保留调试，但证书为会话级，控制端退出后即不可再连）。过网流量全程 TLS 加密，无明文。

**会话 CA 落盘（与 `wdp ca` 同一套签发逻辑）**：push 的临时 CA 不再是纯内存一次性产物，落盘于 `wdp.cfg [agent].push_ca_dir`（默认 `~/.wdp/push-ca`）——CA 有效期 1 天，有效期内跨进程复用同一信任链（`ca.crt`、`push-server.crt|.key`、`push-control.crt|.key`），到期/轮换/损坏时自动重建。产物即普通 wdp ca 文件，`wdp ca show ~/.wdp/push-ca/ca.crt` 可随时检视。

残留兜底：自举注入 `--idle-timeout`（默认 60 分钟，`wdp.cfg [agent].idle_timeout_min` 调整，`<0` 禁用）——控制端崩溃/被杀/断网时 Close 不会被调用，远端 agent 超过空闲周期且无已认证请求即自删退出，不必等 shutdown 信号。`/health` 免认证探测不计入活动，同网段无法给残留 agent 续命；执行中的长任务不判空闲（在途保护）。断线自愈：agent 传输层失败（不可达/断连）时自动重走自举修复后续任务；本次操作不重放——脚本可能已在远端执行，重试会重复非幂等任务。

证书轮换（`wdp.cfg [agent].cert_rotate_min`，缺省不轮换）：共享证书对意味着被攻破的主机配合流量劫持可冒充其他主机（无主机名校验）。配置轮换周期（如 `30` 分钟）后，到期自动换新代信任链并重启 agent、重建直连，把上述冒充窗口压缩为一个周期。轮换惰性触发：只影响仍有后续任务的主机，已执行完自销毁的主机不再轮换。

**自举二进制选择**（按目标平台自动）：自举前经 `uname -sm` 探测目标平台（归一为 `linux_amd64` 这类键），按优先级取用：

1. 主机/组级 `binary_path`（显式指定预编译产物）
2. `wdp.cfg [agent].push_binary.<平台>` 平台表
3. 目标与控制端同平台 → 上传控制端自身（默认行为，同平台无需任何配置）

跨平台且未配置对应二进制时**不做无效上传**，直接回退纯 SSH 并提示缺哪个键（如 `set [agent].push_binary.linux_amd64 in wdp.cfg`）。启动前另有二进制可执行性探测，兜底报 `binary cannot run on this host (control/target platform mismatch?)`。

**跨平台控制端配置**（如 macOS 控制 Linux fleet）：

```sh
./build.sh linux/amd64        # 产出 bin/wdp-linux-amd64
```

```toml
# wdp.cfg
[agent]
[agent.push_binary]
linux_amd64 = "/path/to/bin/wdp-linux-amd64"
```

混合平台 fleet 也可在 inventory 组级按需覆盖（优先级同其它连接参数键：主机条目 > 组 vars > wdp.cfg）：`webarm: {vars: {binary_path: /path/wdp-linux-arm64}}`。

| 层级 | 配置 | 默认 |

## 大规模主机

- 建连并发限流自动生效（2×forks），防千台瞬时握手洪峰
- `--forks` 控制任务并发（默认 5，千台规模建议 20+）
- 压测参考：1000 台 × 5 任务约 5 秒（`scripts/gen-inventory.sh 1000` + `examples/bench`）
