# 04 连接与认证

> **web-console 分支过渡说明**：本分支聚焦常驻 agent 形态，push 通道及其代码已移除（`main` 分支仍保持三通道）。agent 的安装上线由 `wdp server` 承接，两种引导方式按网络可达性选择：
>
> - **纳管脚本拉取**（默认）：目标机能回连 server——控制台生成一次性 token 命令，目标机执行后自行下载二进制与证书；
> - **SSH 推装**：仅 server→目标机单向可达（目标机无法回连）——控制台提交 SSH 凭据，server 主动推装 agent 并注册 systemd，装完走 agent 通道。凭据仅内存态使用，不落库。

> **控制台纳管的信任模型（web-console）**
>
> - **下发纳管脚本必须经 TLS**：脚本以 root 执行，明文通道下中间人替换脚本即等于目标机 root
>   （脚本内嵌的 CA 指纹与脚本同源，只防传输损坏、挡不住主动 MITM）。默认拒绝在明文 HTTP 下
>   生成一键命令；确需在可信内网明文引导时显式加 `--allow-plaintext-enroll`。
> - **SSH 推装凭据同样必须经 TLS 提交**（`POST /api/agents/install`）：请求体携带 root 级
>   SSH 密码/私钥口令，明文 HTTP 下等同广播给链路窃听者。与纳管命令同一门禁口径——
>   可信内网显式加 `--allow-plaintext-enroll` 豁免。
> - **控制台→agent 一律按 mTLS 建连并校验身份**：证书链由自建 CA 保证，主机名按台账地址校验
>   （不再"只验链不验名"——那等于任何一台持本 CA 证书的 agent 都能冒充其它主机）。
> - **不按探活结果回落明文**：启用了纳管信任链的主机探不通就是不可达，不会降级；agent 确未
>   启用 mTLS 的手工台账主机，需要在主机设置里显式勾选「明文通道」（`allow_plaintext`）。
> - **执行记录按作用域裁剪 + 远程命令留执行证据**：`run:view` 可按池/组/标签授予（覆盖语义
>   取代全局授予后，列表/详情/SSE 只见实际触达授权域主机的 run，跨域主机的任务输出不外泄）；
>   远程命令的脚本以 16 KiB 截断快照 + 完整 sha256 落进 run 记录（详情页可查——事后可回答
>   "谁在哪台机执行了什么命令"）。删除执行记录（`run:delete`）仅 admin——operator 可执行但
>   不可销毁执行痕迹。执行/审计/草稿另有保留期清理（`wdp server --runs-retention-days` 等
>   flags，缺省 90/180/30 天，0 = 永久保留）。
> - **逐主机私钥由目标机本地生成（CSR 纳管，docs/20）**：纳管脚本在目标机
>   `wdp agent gencsr` 本地生成密钥并只提交 CSR，server 校验 CSR 自签名后按
>   claim 身份（来源 IP/hostname/绑定名）签发证书——**私钥不落 server 磁盘、
>   不经网络交付**。CSR 提交绑定 claim 来源 IP，token 首次接受 CSR 即锁定到
>   该公钥（同钥幂等重试、异钥 410）。重装复用既有私钥（gencsr 幂等），
>   丢钥重装按 claim 身份换新公钥重签。
> - **控制端客户端证书（`ctl`）自动续期**：显式签发 365 天，剩余不足 30 天时启动即自动续期
>   （保留密钥对）；agent 单元同时写入证书指纹与公钥（SPKI）指纹，后者跨续期依然匹配，
>   因此"pin 控制端身份"与"自动续期"可以同时成立。

连接通道（inventory 主机条目的 `conn` 键选择，缺省 **agent**；`ssh` 保留作引导通道）。所有内置模块在**控制端**实现、只依赖 exec/upload/download 三个原语，因此各通道行为完全一致。

连接参数（`conn`、`agent_port`、`ca_file` 等）可在三个层级配置，高 → 低依次覆盖：

1. **主机条目**：`web1: {conn: agent, agent_port: 7700}`
2. **组级 vars**（含 `all.vars` 与 children 展开，同变量域合并顺序）：
   ```yaml
   all:
     vars:
       conn: agent     # 全 fleet 默认通道
       agent_port: 7602
   ```
3. **wdp.cfg**：`[run].conn`（默认连接类型，空 = agent）与 `[agent].port`（默认端口 7602）

连接参数键是保留键：出现在组 vars 或主机条目时成为连接参数而**不进入模板变量域**——应用变量请避开这些键名（如用 `nginx_port` 而非 `agent_port`）。

## 通道总览

| conn | 场景 | 目标机要求 |
|---|---|---|
| `agent`（默认） | 长期纳管、高频操作 | 常驻 `wdp agent` 进程 |
| `local` | 演练 / CI / 管理本机 | 无（注意：**local 通道忽略 become，不提权**） |
| `ssh`（引导用） | server 经 SSH 推装 agent、临时操作 | POSIX sh（推荐 SFTP） |

## 提权（become）

play 或任务级 `become: true` 后，远端命令经 `sudo` 执行（默认 root，`become_user` 可改）：

```yaml
- hosts: dbservers
  become: true          # play 级：全部任务提权
  tasks:
    - name: 不提权的例外
      shell: id
      become: false     # 任务级覆盖
```

免密 sudo 直接可用；需要密码时 `become_password` / `become_password_env`
（agent 通道经请求体传输、目标机侧密码经 stdin 传给 sudo，不落命令行；仍建议仅在启用 mTLS 的部署使用）。

## Agent 通道（常驻）

目标机启动常驻 agent，控制端 HTTP(S) 直连（免每任务握手）：

```sh
# mTLS 模式（远程纳管的标准姿势，证书签发见下节）
wdp agent --listen 0.0.0.0:7602 --ca ca.crt --cert 10.0.0.13.crt --key 10.0.0.13.key
# 生产建议 systemd 托管（ExecStart=… agent --listen 0.0.0.0:<端口> --ca/--cert/--key
#   --log-file，Restart=always）；安装上线将由 server 纳管流程下发脚本承接
```

安全默认：`wdp agent` **默认仅绑定回环地址**（127.0.0.1），对外（非回环）监听且
未配置 mTLS 时**拒绝启动**——agent 的 `/exec`、`/file` 是命令执行与文件读写
原语，无认证对外监听等于暴露 RCE。可信内网可显式 `--allow-no-auth` 放行。

注意：**回环无认证模式仅限单用户/专用主机**。回环地址对同机所有用户的进程
可达——agent 以 root 常驻时，共享主机上的任意本地用户都能经 127.0.0.1 直接
获得 root 命令执行（启动日志对此有 WARNING 提示）。多用户服务器一律走 mTLS。

inventory（`ca_file`+`cert_file`+`key_file` 为控制端侧 mTLS 三件套）：

```yaml
web1: {conn: agent, host: 10.0.0.13, agent_port: 7602, ca_file: ./ca/ca.crt, cert_file: ./ca/ctl.crt, key_file: ./ca/ctl.key}
web2: {conn: agent, agent_url: 'https://10.0.0.14:7602', ca_file: ./ca/ca.crt, cert_file: ./ca/ctl.crt, key_file: ./ca/ctl.key}
```

IPv6：`host` 填裸 IPv6 字面量即可（各通道自动处理）；手填 `agent_url` 时需按 URL 语法带方括号并加引号（`'https://[fd00::5]:7602'`）；zone ID（`fe80::1%eth0`）不支持。

`wdp agent` 完整参数见 [CLI 参考](12-cli命令参考.md#wdp-agent)。

## mTLS 模式（自建 CA）

适用于跨不可信网络管理 agent。

```sh
wdp ca init ./ca                             # 1. 建 CA（默认 1 天，PathLen=0，私钥明文 0600；--name 自定义文件名）
wdp ca issue ./ca --name 10.0.0.14 --san 10.0.0.14  # 2. agent 服务端证书（输出目录为位置参数；SAN 一律经 --san）
wdp ca issue ./ca --name ctl --profile client  # 3. 控制端客户端证书（输出 SHA256 指纹）
wdp ca init ./ca --days 365                  #    常驻 agent 机群：按需放宽 CA 窗口
```

**叶子有效期自动档**：`ca issue`/`ca renew` 不给 `--days` 时按签发 CA 剩余寿命就近取值——
CA 剩余 ≤30 天（如默认 1 天 CA）叶子**跟随 CA 一起到期**（短会话信任链不留尾巴）；
30~60 天取剩余的 50%（留续期窗口又不越界）；>60 天（长期 CA）上限 30 天。
显式 `--days` 不分段，但**一律不超过 CA 到期**（钳制）。

**自定义根证书**：`issue`/`renew` 的 `--ca-cert/--ca-key` 指向的是**根 CA（签发者）**
——用它给新证书签名，不是要生成的证书本身（新证书输出到 `<输出目录>/<name>.crt|.key`，输出目录为位置参数，缺省 `.`）。
默认取 `<dir>/ca.crt|ca.key`；指向 openssl 等自制的组织根 CA（明文 SEC1 EC /
PKCS8 私钥）即可复用既有信任链，无需任何导入步骤。校验：必须是 CA 证书、
未过期、与私钥匹配。

**短有效期取代静态加密**：CA 私钥不再做口令加密（PBKDF2/AES 信封已移除），
一律明文 0600、目录 0700。默认 1 天的 CA 是远程部署的短周期会话信任根，
泄漏窗口天然受限——静态加密所防的"密钥文件被拷走"威胁在一天的有效期面前
收益极小，而口令分发/注入本身又是新的泄漏面。常驻机群用 `--days` 放宽后，
依靠文件权限与专用控制节点隔离即可。

多地址主机（内外网双 IP、NAT、堡垒机端口转发）用 `--san` 一次覆盖全部可达地址，
无需为每个地址单独签证书、也无需按主机降级 `insecure_skip_verify`：

```sh
wdp ca issue ./ca --name 10.0.0.14 --san 10.0.0.14 --san 192.168.1.14 --san web1.internal
# renew 续期时 SAN 全量继承，无需重述
```

agent 端带证书与指纹准许名单启动：

```sh
wdp agent --listen 0.0.0.0:7602 --ca ca.crt --cert 10.0.0.14.crt \
    --key 10.0.0.14.key --pin-client-fp sha256:<ctl指纹>
```

inventory 端：

```yaml
web1:
  conn: agent
  host: 10.0.0.14
  agent_port: 7602
  tls: true
  ca_file: ca/ca.crt          # 不配则信任系统证书池（公网 CA 场景）
  cert_file: ca/ctl.crt
  key_file: ca/ctl.key
  # tls_server_name: other     # 一般无需填写：默认已按 host 字段（未填即主机名）校验；
                               # 仅当证书 SAN 是其它名称时显式指定
  # tls_skip_host_verify: true # 仅跳过主机名校验，保留 CA 链校验
```

控制端对 agent 服务端证书的校验强度（从强到弱）：

| 配置 | 链校验 | 主机名（SAN）校验 |
|---|---|---|
| 默认 | ✔（`ca_file` 或系统池） | ✔（证书 SAN 含 **host 字段 / inventory 主机名** 即可——端口转发、NAT 场景经 `agent_url` 连入时默认按逻辑身份而非入口地址校验） |
| `tls_server_name: <名称>` | ✔ | ✔（显式改按该名称） |
| `tls_skip_host_verify: true` | ✔ | ✘ |
| `insecure_skip_verify: true` | ✘ | ✘ |

所以给 agent 签证书时 `--name` 直接用 inventory 主机名或 `host` 字段值，
端口转发/NAT 入口地址与证书不一致也无需额外配置。

agent 端对控制端只做证书链校验（客户端证书无主机名概念），可再用 `--pin-client-fp`
钉住具体指纹实现精确吊销。

证书安全设计：

- **短周期 + 更新延期**：`wdp ca renew <证书路径> --days N` 原地延期（`--days` 为增量，字段全继承，旧件自动备份 `*.old.<时间戳>`）；`--new-key` 换钥即吊销旧证书
- **指纹准许名单（精确吊销）**：`--pin-client-fp` 可多次；撤权 = 删指纹重启 agent，

- **明确降级**：`tls_skip_host_verify`（保链跳名）/ `insecure_skip_verify`（全跳过），测试环境用
- 无 CRL/OCSP：吊销依赖指纹名单与短周期轮换

### 运维端点（mTLS 保护，常驻 agent 日常运维）

| 端点 | 用途 |
|---|---|
| `GET /health` | 探活 + `cert_not_after`（服务端证书到期时刻）+ `idle_timeout_sec` / `idle_left_sec`，可批量巡检证书剩余有效期 |
| `POST /shutdown` | 优雅退出并自清理（无额外开关：无认证模式直接执行，mTLS 模式经客户端证书/pin 校验后执行）。请求体**空或空 JSON `{}`** 即默认清理（全部 best-effort，单项失败只记日志）：删除自身二进制、证书材料（cert/key/**含 CA**）、停用并**删除 systemd 单元文件**（disable + 删文件 + daemon-reload，默认 `wdp-agent`，`--systemd-unit` 按实际部署名指定；非 systemd 环境静默跳过）。也可传 JSON 指定清理项一并执行：`{"systemd_unit":"<单元名>","files":["/path/..."]}`（files 为文件或目录，且**限定在 agent 领地内**——自身二进制及其附属（`.log`/`.pid`/自删残留）、证书材料所在目录、runs 持久化根目录；越界路径拒绝并在响应 `refused_files` 里列出，根路径拒删防手滑）。`--cleanup-on-shutdown` 只影响**空闲超时退出**是否自清理，`/shutdown` 显式信号总是清理 |
| `GET /logs` | 拉取近期日志（内存环形缓冲，约最近 512KiB，text/plain）。与其它业务端点同认证；控制端 `wdp agentctl logs` 逐主机拉取落盘。完整历史走 `--log-file` 落盘后经 `GET /file` 拉取 |

### 文件领地（`--allow-file-path`，opt-in）

`PUT/GET /file` 与 `POST /archive` 对持有客户端证书的一方是**任意路径读写**
原语（部署语义使然，缺省不限制）。`/shutdown` 的 `files` 参数早已收紧到
agent 领地（见上表）；`--allow-file-path <目录>`（可重复）提供等价的
opt-in 收紧——启用后上传/下载/解压的路径必须落在列出的目录树内，越界
一律 403 并记 warn 日志：

```sh
# 例：只允许部署物落在 /opt 与 /srv，且日志可回拉
wdp agent --listen 0.0.0.0:7602 --ca ... --cert ... --key ... \
  --allow-file-path /opt --allow-file-path /srv
```

- 判定为词法口径（Abs + Clean + 前缀），与 `/shutdown` 领地判定一致；
  领地内的符号链接仍可指向领地外——领地目录树若可被其他用户写，须自行保证
- **远程升级**经 `/file` 上传到 agent 二进制同目录的临时文件：启用本开关后，
  清单须包含 agent 二进制所在目录（如 `/usr/local/bin`），否则升级会被 403 拒绝
- `/exec` 不在收紧范围——部署工具的执行语义即全权，收紧执行面的手段是
  mTLS + `--pin-client-fp`（见上节）
- 相对路径与文件系统根会被启动参数校验拒绝（相对路径随工作目录漂移、
  根等于没设）

### 运行日志（slog）

agent 内置 slog 日志内核，扇出到三个目的地：**stderr**（始终，systemd 托管时进 journal）、**`--log-file <路径>`**（可选，追加写、自动建父目录、0600；**自清理不删除该文件**——退役后保留供审计，确要删须显式列入 `/shutdown` 的 `files`）、**内存环形缓冲**（始终，约 512KiB，`GET /logs` / `agentctl logs` 拉取）。

级别由 `--log-level` 控制（默认 `info`）：

| 级别 | 内容 |
|---|---|
| `info`（默认） | 必要运行记录：执行的命令（超长截断）、上传/下载的文件与字节数、解压 src→dest 与文件数、换证与到期时间、收到关闭信号、自清理动作、空闲退出 |
| `debug` | info 之上记录**每一次操作**的完整细节：命令的 user/cwd/超时/环境变量数/退出码/输出量、逐请求访问日志（方法/路径/状态/耗时，仅已认证请求；`/health` 探测不记） |
| `trace` | debug 之上对每个请求/响应做 **httpdump**（头全量、体截断至 4KiB，`become_password`/私钥等敏感字段值一律遮蔽 `***`） |
| `warn` / `error` | 仅告警与错误（清理失败、换证被拒等） |

控制端汇集：`wdp agentctl logs <主机模式>` 拉取所有匹配 agent 的近期日志，逐主机写入 `--out` 目录（默认 `./wdp-agent-logs/<host>.log`），即"agent 日志传输到控制端、用文件记录"。

证书到期巡检：`wdp agentctl status` 批量查看 `cert_not_after` 剩余天数。
远程热换证书（server 下发 + 重启的连锁更换）随纳管流程提供；现阶段更换证书
= `wdp ca issue` 重签后传到目标机重启 agent。

**吊销泄漏的客户端证书规程**：移除 `--pin-client-fp` 中的指纹并重启目标
agent 即生效（存量连接随重启断开）。

敏感操作（远程换证、远程清理、空闲自动退出）均输出事件日志（见"运行日志"小节），
systemd 托管时进 journal 可追溯。

## 大规模主机

- 建连并发限流自动生效（2×forks），防千台瞬时握手洪峰
- `--forks` 控制任务并发（默认 5，千台规模建议 20+）
- 压测参考：1000 台 × 5 任务约 5 秒（需自建千台清单；仓库内未附带压测样例）
