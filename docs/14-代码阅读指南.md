## 1. wdp 是什么（一分钟版）

wdp 是一个用 Go 写的**自动化部署工具**，对标 Ansible：

- 你在**一台控制机**上运行它，它通过 SSH（或 agent）把命令/文件发到**成百上千台目标机**上执行；
- 部署内容打包成 **chart**（一个目录/tgz，含配置、模板、任务清单），类似 Helm 的 chart；
- 任务清单是 **playbook**（YAML），语法风格接近 Ansible playbook；
- 产物是**单个静态二进制**，目标机上只需要 POSIX sh（连 Python 都不要——这是与 Ansible 最大的工程差异）。

```sh
wdp run ./examples/docker -i examples/inventory.yaml   # 部署
wdp run ./examples/docker --check --diff -i ...        # 零风险预演
```

## 2. 核心概念：先搞懂这 7 个词

读代码前先把这些词变成直觉。可以用"装修队"来类比：

| 概念 | 是什么 | 类比 | 代码里的类型 |
|---|---|---|---|
| **inventory（主机清单）** | 全部目标机的花名册：分组、地址、每台的变量 | 施工队名单 | `model.Host` / `model.Group` / `inventory.Inventory` |
| **playbook** | 一份任务清单文件（YAML），由若干 play 组成 | 施工图纸 | `[]*model.Play` |
| **play** | 图纸上的一页：**选一批主机** + 按顺序执行的任务列表 | 某一层楼的工序 | `model.Play` |
| **task（任务）** | 最小执行单元：一个模块调用 + 控制属性（when/loop/…） | 一道工序 | `model.Task` |
| **module（模块）** | 真正干活的动作：shell/copy/template/file… 23 个内置 | 工人的技能 | `module.Module` 接口 |
| **chart（应用包）** | 自包含部署单元：values + 模板 + 任务清单 + 生命周期 | 整个项目的施工包 | `chart.Chart` |
| **values** | chart 的配置数据，三层叠加（默认 → -f 文件 → --set） | 材料清单 | `map[string]any` |

关系串起来：

```
inventory（对谁做）
     │
     ▼
playbook = [ play1, play2, ... ]        play = 主机选择 + tasks
     │                                        │
     ▼                                        ▼
chart 装着 playbook（deploy.yaml）+ values + templates/
     │
     ▼
task → module.Run() → conn.Exec() ──► 远端 /bin/sh
```

另外几个次级概念（用到再查）：

- **phase（相位）**：chart 根目录的一个 `<phase>.yaml` 文件就是一个相位（deploy/uninstall/status/update…），`--phase` 选择执行哪个；
- **handler**：由任务 `notify` 触发的"重载/重启"类任务，play 末尾统一执行；
- **facts**：从目标机采集的运行时数据（OS、内存…），采回来变成变量；
- **marker（release marker）**：部署成功后在目标机写的 `/var/lib/wdp/<chart>/release.json`，漂移检测靠它；
- **channel（通道）**：控制机与目标机的通信方式，共 4 种：`ssh` / `agent`（常驻）/ `push`（临时 agent）/ `local`。

## 3. 代码全景：目录与分层

```
wdp/
├── cmd/wdp/main.go          # 入口：只有一行 os.Exit(cli.Execute())
├── internal/                # 全部实现（internal = 外部不可导入）
│   ├── cli/                 # ① 组合根：cobra 命令树，装配一切（24 文件）
│   ├── executor/            # ② 编排引擎：play→批次→主机→任务（15 文件）
│   ├── module/              # ③ 动作层：23 个内置模块（30 文件）
│   ├── conn/                # ④ 传输抽象 + 4 种通道实现
│   │   ├── sshc/            #    SSH 通道（含脚本组装 WrapScript）
│   │   ├── agentc/          #    常驻 agent 客户端（HTTPS+mTLS）
│   │   ├── push/            #    push 临时 agent（SSH 自举 agent 再直连）
│   │   ├── local/           #    本地执行（delegate_to: localhost）
│   │   └── fake/            #    测试专用假连接（生产禁止引用）
│   ├── agent/               #    agent 服务端（跑在目标机上的那半个）
│   ├── playbook/            # ⑤ playbook YAML 解析 + include 展开 + lint
│   ├── chart/               # ⑥ chart 加载/values 合并/相位/schema/lint/打包
│   ├── inventory/           # ⑦ 主机清单解析、选择模式、动态组
│   ├── render/              # ⑧ Go 模板引擎封装（sprig 白名单）
│   ├── model/               # ⑨ 纯数据定义（Play/Task/Host/Result…）
│   ├── report/              # ⑩ 输出层：控制台/JSON/RECAP/表格
│   ├── config/              #    wdp.cfg 配置（TOML）
│   ├── release/             #    部署记录（~/.wdp/releases）
│   ├── drift/               #    漂移检测内核
│   ├── ca/                  #    自建 PKI（mTLS 证书签发）
│   ├── agentops/            #    agent 运维操作（安装/换证/退役）
│   ├── knownhosts/ sshcfg/ pushcerts/  # SSH 指纹/ssh config/会话 CA
│   └── fmtutil/ shellquote/ dumphttp/  # 小工具（表格/引用/脱敏）
├── examples/                # 可运行示例（docker / node-exporter）
└── docs/                    # 你正在读的文档
```

**分层依赖图**（箭头 = "调用"）：

```
            cmd/wdp
               │
               ▼
   ┌───────  cli（组合根）─────────────┐
   │  装配：config→inventory→chart→    │
   │  executor→conn→report             │
   └──┬──────────┬──────────┬─────────┘
      ▼          ▼          ▼
  playbook     chart      executor ────► report
      │          │           │
      └────┬─────┘           ├──────► module（动作）
           ▼                 │            │
         model ◄─────────────┤            ▼
           │                 ▼          conn（传输）
           │             render             │
           │                 │         ┌────┴────┬────────┬──────┐
           ▼                 ▼         ▼         ▼        ▼      ▼
        （纯数据，无内部依赖）         sshc     agentc    push   local
```

三条铁律（理解了它们就理解了一半设计）：

1. **model 是纯数据包**，不 import 任何内部包——所有层共用同一套结构体；
2. **module 只依赖 conn 原语**（Exec/Upload/Download），不知道自己跑在 SSH 还是 agent 上；
3. **conn 层不读配置**——配置由 cli（组合根）归一成 `conn.Defaults` 显式注入，方便测试。

## 4. 一条命令的完整旅程

以 `wdp run ./examples/docker -i examples/inventory.yaml` 为例。
这是全项目最重要的主线，建议对照源码走一遍。

### 第 0 站：入口与配置

1. `cmd/wdp/main.go` → `cli.Execute()`；
2. `internal/cli/root.go` `NewRootCmd()`：构建 cobra 命令树；
   `PersistentPreRunE()`：加载 `wdp.cfg`（`internal/config/config.go` `Load()`），
   把配置回填到各 flag 缺省值；
3. 进入 `run` 命令的 RunE → `internal/cli/run.go` `runTarget()`（**主装配函数，读透它 = 读懂一半 cli 包**）。

### 第 1 站：加载输入（三样东西）

在 `runTarget()` 里依次：

- **inventory**：`loadInventories()`（cli/common.go）→ `inventory.LoadMergeWithConfig()`
  → `build()`：解析 YAML、合并 group/host 变量（`vars.go` `applyVars()`），
  结果是 `inventory.Inventory`（主机名 → `model.Host`，组名 → 成员）；
- **chart**：`chart.OpenWithLimits()`（chart/chart.go）干三件事：
  - `loadDir()`：读 chart.yaml/values.yaml/deploy.yaml/相位文件/子 chart；
  - `BuildValues()`（values.go）：三层合并 defaults → -f → --set；
  - `render.NewEngine()`：把 `_helpers.tpl` 编译进模板引擎；
- **相位选择**：`ch.PhasePlays(phase)`（lifecycle.go）拿到要执行的 play 列表
  （deploy.yaml 里的，或 --phase 指定的其它相位文件）。

### 第 2 站：执行前校验

仍在 `runTarget()`：

- `ValidateRequired()` + `ValidateValuesSchema()`：必填项与 JSON Schema 校验
  （部署相位才做，坏配置在**碰任何主机之前**被拦截）；
- `confirmReversibility()`：统计不可逆操作并交互确认（--yes 跳过）；
- `reportValueCollisions()`：inventory 变量被 values 遮蔽的告警。

### 第 3 站：装配执行器

```go
rep := buildReporter()                    // 控制台 或 --output json
conns := conn.NewManagerWithDefaults(...) // 连接缓存管理器
ex := executor.New(inv, conns, rep, eopts)
```

### 第 4 站：执行引擎（executor 包，核心中的核心）

调用链（全部在 internal/executor/）：

```
ex.Run()                    executor.go   遍历 plays
 └─ runPlay()               play.go       单个 play 的推进
     ├─ selectHosts()       hosts.go      hosts 模式 → 主机列表（含 --limit）
     ├─ splitHookTasks()    executor.go   分出 pre_/post_ hook 任务
     ├─ runMainBatches()    play.go       按 serial/strategy 切批次
     │   └─ runBatch()      batch.go      单批次：逐任务推进
     │       ├─ prepareBatchRuns()  batch.go  组装每台主机的变量域
     │       └─ 对每个任务：
     │           flushHandlers 前提下 fanOut()   batch.go
     │           （forks 信号量限流的 goroutine 池）
     │             └─ runTaskOnHost()   task.go  ★ 单任务分发
     ├─ flushHandlers()     batch.go      notify 触发的 handler 统一执行
     └─ finishPlay()        play.go       RECAP、写/清 marker、记 release
```

`runTaskOnHost()`（task.go）是**单任务的总调度**，值得整读：

1. `evalWhen()`：条件不满足 → skipped；
2. `ChartRef != ""` → `runChartTask()`（expand.go）：子 chart 展开（作用域切换 + 递归）；
3. `Block != nil` → `runBlock()`：block/rescue/always 容错组；
4. 委托解析 `resolveDelegate()`（delegate_to）；
5. loop 渲染 + 逐项 → `execModule()`（exec.go）。

### 第 5 站：execModule——任务落到模块（exec.go）

`execModule()` 做：

1. 渲染任务参数（模板引擎把 `{{ .app.port }}` 变成真实值）；
2. `e.Conns.Get(ctx, host)`：从 Manager 拿连接（首次会 `Connect()` 握手）；
3. `resolveModule()` → `module.Resolve()`（module/module.go）：内置注册表优先，
   其次 chart 携带的脚本模块（`modules/<name>`）；
4. 构造 `module.RunContext`（runctx.go：连接/变量/引擎/check/diff/回滚上下文）；
5. `mod.Run(rc, args, free)` → 返回 `module.Result`；
6. `applyModuleResult()`：结果落库——register 变量、facts、动态组、notify。

### 第 6 站：传输层——命令真正到远端

以 shell 任务 + SSH 通道为例：

```
module/exec.go  ShellModule.Run()
  → rc.exec(script)                    module/runctx.go（拼 env/become）
    → conn.Exec(ExecRequest{Script…})  conn 接口
      → sshc.Conn.Exec()               conn/sshc/exec.go
        → WrapScript()                 ★ 脚本组装核心（见 §6.1）
          → SSH session 运行，字节到达远端 /bin/sh
```

（若是 agent 通道：`conn/agentc` 发 HTTPS `POST /exec`，
目标机上的 `internal/agent` 服务端接收并本地执行——见 §6.6。）

### 第 7 站：结果回流

`ExecResult{Code,Stdout,Stderr}` 一路返回成 `module.Result` → `model.TaskResult`：

- `e.Rep.HostResult()`：report 包渲染到你屏幕上那一行；
- 统计进 `Stats`（play 结束打 RECAP 表）；
- `finishPlay()`：部署相位成功 → `writeMarkers()` 把 release.json 写到每台机；
- 回到 `runTarget()`：`conns.CloseAll()`、`release.Save()` 落部署记录。

## 5. 包导读（按依赖层次）

以下每个包给出：**职责一句话 → 必读文件 → 关键类型 → 小白提示**。
建议阅读顺序 = 本节顺序（自顶向下，先见森林再见树木）。

### 5.1 internal/cli —— 组合根（24 文件）

**职责**：cobra 命令树 + 装配车间。把 config/inventory/chart/executor/conn/report
拼在一起；本身不含领域逻辑。

- 必读：`root.go`（命令树 + 全局 flag）、`run.go` 的 `runTarget()`（主装配线）、
  `common.go`（共享装配件）、`output.go`（选 reporter）；
- 其余文件基本一个命令一个：`adhoc` / `lint` / `render` / `drift` / `package` /
  `module` / `schema` / `release` / `inv`（别名 inventory）/ `agent` / `agentctl` /
  `ca` / `scan-ssh` / `plan` / `apply`；
- 命令分组：Deployment(run,plan,apply,adhoc) / Package(schema,module,render,lint,package) /
  Security(ca,scan-ssh) / Agent(agent,agentctl) / Operations(drift,release,inv)；
- **小白提示**：找"某个 flag 从哪进来"→ 先 grep `Flags()`；找"某个命令做了什么"
  → 看它 RunE 调了哪个内部包的函数。common.go:17-20 有四个 blank import——
  那是在注册连接工厂（§6.6），删了 SSH 就没了。

### 5.2 internal/executor —— 编排引擎（15 文件）

**职责**：按 play 推进任务，forks 并发扇出到主机，处理 when/loop/register/
notify/handler/策略分批/自动回滚/chart 展开。

- 必读顺序：`executor.go`（三大结构体）→ `play.go` → `batch.go` → `task.go` →
  `exec.go` → `expand.go`；
- 三个关键结构体（executor.go）：
  - `Options`：执行选项（forks/tags/check/phase/chart/values…），cli 装配时填；
  - `Executor`：引擎本体（inventory/连接管理器/reporter + facts/stats/deadHosts）；
  - `hostRun`：**单主机**在单 play 内的运行态（变量域/通知集/变更日志）；
- 变量域组装在 `batch.go` `prepareBatchRuns()` 与 `builtins.go`
  （`inventory_hostname` 等 8 个内置变量在 `builtinVarNames`，是唯一清单）；
- 分批与策略：`hosts.go` `splitBatches()`（serial 三种写法）+
  `strategy.go`（rolling/canary/健康门/`rollbackBatch()` 回滚）；
- **小白提示**：并发都在 `batch.go` `fanOut()`（信号量限流 goroutine），
  读 executor 时脑子里要分清三层循环：play → task → host；
  register/facts 跨批次靠 `playState` 延续（executor.go `playState`）。

### 5.3 internal/module —— 动作层（30 文件）

**职责**：23 个内置模块。框架文件 5 个，其余一模块一文件。

- 框架必读：
  - `module.go`：`Module` 接口（仅 3 个方法）、`Result` 结构（模块能往回传什么：
    changed/failed/stdout/**Facts/Groups/AddHost/Diff**——后三个是特殊通道）、
    `Resolve()`（内置优先 → chart 脚本模块）；
  - `runctx.go`：`RunContext`（模块能看到的世界）+ `exec()` 快捷方法；
  - `args.go`：参数校验（未知参数报错带"你是不是想写…"的编辑距离提示）；
  - `chartmodule.go`：chart 自带脚本模块的执行契约（§6.7）；
- 模块实现看两个就懂套路：`exec.go`（shell，最简单）和 `fileops.go`
  （copy/template 共用的 sha256 对比 + diff 生成）；
- `wdp module <名字>` 可打印任意模块的参数文档——文档与代码同源
  （`UsageProvider` 接口），**这是查模块用法最快的方式**；
- **小白提示**：模块实现必须无状态（全局单例注册）；判断"是否变更"
  （changed）是每个幂等模块的核心逻辑，读模块时重点看它怎么对比现状。

### 5.4 internal/conn —— 传输层

**职责**：把"执行脚本/传文件"抽象成 5 个方法的接口，4 种实现。

- 必读：`connection.go`（接口全文只有 ~70 行，是全项目最重要的接口）+
  `manager.go`（连接缓存，`Get()` 幂等握手）；
- 四通道一句话：
  - `sshc`：每次执行开 SSH session；`WrapScript()` 把脚本 base64 化避免引号地狱；
  - `agentc`：HTTPS+mTLS 连常驻 agent（目标机 7602 端口），无 SSH 开销；
  - `push`：先用 SSH 把 agent 二进制+证书推上去临时拉起，再直连 agent，
    结束自毁——"零预装又要快"的折中；
  - `local`：本机 `/bin/sh`（`delegate_to: localhost` 用）；
- **小白提示**：`Host.Conn` 字段决定用哪个工厂（`RegisterFactory` 注册表）；
  agent 通道比 SSH 快的秘密：复用 HTTP 连接且解压可在 agent 侧 Go 原生完成
  （`NativeExtractor` 能力接口，unarchive 模块会探测）。

### 5.5 internal/model —— 纯数据（4 文件）

**职责**：全项目共享的结构体，无任何逻辑、无任何内部依赖。

- `play.go`：`Play` / `Task`（**任务的全部控制属性都在这个结构体里**，
  想知道 playbook 支持什么，读它的字段注释最快）/ `Strategy`；
- `host.go`：`Host`（~40 字段，按通道分组）；
- `result.go`：`TaskResult`（含 JSON tag——`--output json` 的字段名来源）、`Stats`。

### 5.6 internal/playbook —— 清单解析（6 文件）

**职责**：YAML → `[]*model.Play`。

- `playbook.go` `Parse()`：半结构化解析——已知字段走 yaml tag，
  tasks/handlers 里"模块键"动态识别；
- `task.go` `resolveTaskModule()`：**任务解析的核心**——已知控制键之外
  剩下的唯一键就是模块（所以两个模块键会报错）；
- `include.go`：`include:` 在**加载期**静态展开（import 语义），
  when/tags/become 下沉进片段任务；
- `lint.go`：裸 playbook 的静态检查。

### 5.7 internal/chart —— 应用包（14 文件）

**职责**：chart 的加载、values 三层合并、相位生命周期、子 chart、校验、打包。

- 必读：`chart.go`（`loadDir()` 递归加载）→ `values.go`（`Merge()` 深合并 +
  `SubScope()` 子 chart 作用域——§6.3）→ `lifecycle.go`（相位属性/EntryPlay）
  → `lint.go`；
- 次级：`schema.go`（values.schema.json）、`subchart.go`（`jdk@^1.2` 版本约束）、
  `marker.go` / `reversibility.go` / `package.go` / `tgz.go`；
- **小白提示**：chart 包只负责"装载与静态校验"，执行仍归 executor——
  `deploy.yaml` 解析后就是普通 play，chart 任务由 executor 的 expand.go 展开。

### 5.8 internal/render —— 模板引擎（5 文件）

**职责**：Go text/template 封装 + sprig 白名单 + 自有函数。

- `engine.go`：`Engine.Render()`（渲染字符串）/ `RenderValue()`（渲染任意结构），
  **missingkey=error**——拼错变量名直接报错而不是静默空串；
- `allowlist.go`：sprig 函数白名单（证书生成/env 读取等危险函数被排除，
  注释里写了安全理由）；
- `validate.go`：`ValidateTaskTemplates()` lint 用的 parse-only 校验。

### 5.9 internal/inventory —— 主机清单（10 文件）

**职责**：YAML 清单 → `Inventory`；主机选择模式；运行期动态组。

- `select.go` `Select()`：hosts 模式解析（逗号并集/`!`排除/`:&`交集/通配符）——
  "为什么我的 hosts 写法没选中机器"看这里；
- `host.go`：主机字段白名单 + `~/.ssh/config` 合并（internal/sshcfg）；
- `topology.go`：`groups`/`hosts` 内置变量的数据源 + `group_by`/`add_host`
  的运行期落点（`AddDynamicGroup` / `AddRuntimeHost`）。

### 5.10 internal/report —— 输出层（8 文件）

**职责**：`Reporter` 接口 + 控制台实现（-v/-q 级别、颜色、任务行、RECAP 表）
+ JSON 实现。

- `report.go`：接口只有 8 个方法；`row.go`：任务行怎么渲染
  （output=tail/head/full 与 diff 块在这里生效）；
- **小白提示**：executor 只调 `Rep.Xxx()`，不关心输出形态——
  所以加新输出格式 = 实现一个 Reporter。

## 6. 关键机制深入阅读（专题）

### 6.1 一个 shell 任务如何变成远端命令

**问题**：控制机上的 `shell: 'echo {{ .app.port }}'` 怎么安全到达远端？

**入口**：`conn/sshc/exec.go` `WrapScript()`。它解决三件事：

1. 引号/注入：不直接拼接，而是把"环境变量导出 + 用户脚本"整体 **base64 编码**，
   在远端解码到 `mktemp` 临时文件再 `sh "$T"` 执行；
2. 提权：`become_user` 时包一层 `sudo -n -u <user> -- sh "$T"`，
   sudo 密码走 session stdin（先 `sudo -S -v` 预热）；
3. 清理：执行完 `rm -f` 临时文件。

**阅读路线**：`executor/exec.go execModule()` → `module/runctx.go exec()` →
`conn/sshc/exec.go Exec()` → `WrapScript()`。读完这条链，
任何"远端执行结果奇怪"的问题你都知道在哪打断点。

### 6.2 变量从哪来：优先级与渲染时机

**变量域不是一开始就有的，是分三层逐步组装的**（读 `batch.go`
`prepareBatchRuns()` 和 `executor.go` 的注释）：

```
静态层（装配期）：inventory vars < chart values < play vars
运行层（批次期）：register/facts 结果叠加（playState.seed）
内置层（最后注入）：inventory_hostname 等 8 个（不可覆盖）
```

chart 引用任务还有独立作用域（§6.3）。**渲染时机**：任务参数在 `execModule()`
里才渲染（`engine.RenderValue`）——所以 register 一个变量后**下一个任务**立刻可用；
模板拼错变量名在渲染时报错（missingkey=error），lint 也能提前抓一部分
（`render/validate.go`）。

### 6.3 chart 作用域隔离：SubScope

**问题**：父 chart 引用子 chart `jdk` 时，jdk 的任务能看到哪些值？

**入口**：`chart/values.go` `SubScope()`——四层：

```
子 chart 默认 values → 父 values 的 jdk: 子树 → global:（跨层共享） → 引用 vars
```

子 chart **看不到**父的兄弟子树（如 `app:`），这保证组件可移植。
执行侧消费点在 `executor/expand.go` `runChartTask()`（切作用域→递归→恢复），
lint/render 预览用同一函数保证不漂移。深度上限 32 防环引用
（`executor.go` `maxChartDepth`）。

### 6.4 check / diff 预演怎么实现

**check**：`Options.CheckMode` 一路传进 `RunContext.CheckMode`，模块自己判断
（例：copy 发现内容一致 → changed=false；不一致 → 只报告 changed 不写入）。
脚本模块默认跳过，chart.yaml 声明 `check_mode: supported` 才预演
（`module/chartmodule.go`，`WDP_CHECK=1` 环境变量通知脚本）。

**diff**：`DiffMode` 下模块算出 unified diff 放进 `Result.Diff`
（`module/fileops.go` 用 go-difflib），report 的 `row.go` 负责展示。

### 6.5 自动回滚：journal + 快照

**入口**：`executor/strategy.go` `rollbackBatch()`。

机制：play 声明 `auto_rollback` 时，每个**文件类变更**（copy/template/file/
unarchive）执行前先在远端做快照（shadow 目录），同时往该主机的
`hostRun.journal` 记一条 `module.RollbackAction`（restore/remove 两类）。
批次失败或健康门未过 → 逆序重放 journal（`cp -a` 恢复 / `rm -rf` 删除新建）。
模块侧通过 `RollbackProvider` 接口声明自己的回滚能力
（copy/template/file = Full，unarchive = Partial，shell = None）。

### 6.6 四种通道怎么选、agent 是什么

- **ssh**：零预装要求，每任务开 session，最通用最慢；
- **agent**：目标机常驻 `internal/agent` 服务端（默认 127.0.0.1:7602），
  mTLS 双向认证，HTTPS 复用连接；还提供 agent 侧原生解压（`NativeExtractor`）；
- **push**：`conn/push` 的自举流程（package 注释写得很清楚，值得整读）：
  SSH 上传二进制+会话证书 → 远端拉起 agent → 直连 HTTPS → 结束 `/shutdown`
  自清理；传输故障自动重自举（`heal.go`），自举失败退回纯 SSH；
- **local**：`delegate_to: localhost` 与 CI 用。

服务端 `internal/agent`：`handler.go` 路由 6 个端点，`exec.go` 做提权执行
（密码走 stdin 不进 argv），`clean.go` 负责自删除。

### 6.7 chart 自带脚本模块（无源码扩展）

chart 的 `modules/<name>` 普通文件 = 一个自定义模块（`module/chartmodule.go`）：
上传到远端 `/tmp/.wdp-mod-<rand>` 执行，参数以 `WDP_MODULE_ARGS`（JSON）
环境变量传入，脚本 stdout 输出 JSON `{changed,failed,msg}` 即结果契约。
这是"不改 Go 源码加能力"的正路。

## 7. 排错速查：从现象到代码

通用方法：**报错信息里的关键短语 → 全文搜索**。下表是高频入口：

| 现象/报错关键词 | 大概率位置 | 说明 |
|---|---|---|
| `missing required config items` | chart/lifecycle.go `ValidateRequired` | required 点路径缺失 |
| `values do not match values.schema.json` | chart/schema.go | values 类型/取值违约 |
| `unknown --phase` / `unknown tasks_from phase` | chart/lifecycle.go `PhasePlays/EntryPlay` | 相位名拼错，报错会列出可用相位 |
| `specifies multiple modules` | playbook/task.go `resolveTaskModule` | 任务写了两个模块键 |
| `map has no entry for key "xxx"` | render/engine.go | 模板引用了不存在的变量（missingkey=error） |
| `task "x" uses unknown module` | chart/lint.go 或 playbook/lint.go | 模块名拼错；`wdp module` 查合法名单 |
| `failed to reference subchart` | chart/subchart.go `ResolveSub` | 子 chart 名/版本约束不满足 |
| `exceeded the depth limit 32` | executor/expand.go | chart 引用成环 |
| `UNREACHABLE`（结果里） | conn 各通道 `Connect`/`Exec` | 连不上：网络/认证/超时，看 stderr 详情 |
| `handler "x" duplicated` | executor/handlers.go | 子 chart handler 与父重名，被忽略 |
| include 相关 `no tasks`/深度超限 | playbook/include.go | 片段为空或循环引用 |
| 参数 `did you mean` | module/args.go `ValidateArgs` | 模块参数名拼错 |
| 表格乱码/对不齐 | fmtutil/width.go | CJK 宽度计算，非 bug 高发区 |

**排查一个真实执行问题的三板斧**：

1. `wdp run <chart> --check --diff -i ...`：零风险预演，先看任务树对不对；
2. `-v`（可叠到 -vvv）提高 verbosity：report 包会输出更多细节
   （`report/report.go` 级别定义）；
3. 单主机收窄 `--limit <host>` + `--start-at-task "任务名"`：从失败任务直接续跑。

**认证类**：SSH 排 `conn/sshc/auth.go`（密钥合并逻辑有详细注释）与
`hostkey.go`（known_hosts 校验、MITM 提示）；agent 排 `conn/agentc/tls.go`
（证书/CA/服务器名三方不一致的报错都在这）。

## 8. 测试与调试方法

### 跑测试

```sh
go test ./...                 # 全量
go test ./internal/executor/ -run TestChartTaskScoping -v   # 单测
```

### 测试体系怎么读（照葫芦画瓢写新测试）

- **fake 连接**（`conn/fake`）：内存版 Conn，记录每次 `ExecLog` 和上传的
  `Files`——executor 测试断言"生成的脚本内容是否正确"就是查这个日志；
- **captureReporter**（executor 测试文件里）：把 reporter 事件记成字符串，
  `joined()` 后做子串断言；
- **chart fixture**：`t.TempDir()` + 内联 YAML 写一个临时 chart
  （参考 chart/phase_test.go 的 `writePhaseChart` / executor/chart_test.go 的
  `writeTestChart`）；

- 用 delve：`dlv debug ./cmd/wdp -- run ./examples/node-exporter --check -i examples/inventory.yaml`；
- 临时日志：executor/report 层有现成钩子（`Rep.PlayMsg`），模块层可直接

## 9. 动手改代码：两个最小练习

### 练习 A：给 shell 模块加一个参数（热身）

1. 打开 `internal/module/exec.go`（shell/command 模块）；
2. `args.go` 的校验是"未知参数报错"驱动的——先在参数解析处加你的键；
3. 若要进文档：给模块实现 `Params()`（`UsageProvider`），
   `wdp module shell` 立刻可见；
4. 在同包测试里加一个 `TestXxx`（用 fake conn），`go test` 过即成。

### 练习 B：写一个最简内置模块（比如 `hostname` 返回主机名）

1. 新建 `internal/module/hostname.go`：

```go
type HostnameModule struct{}

func (m *HostnameModule) Name() string { return "hostname" }
func (m *HostnameModule) Desc() string { return "print the remote hostname" }
func (m *HostnameModule) Run(rc *RunContext, args map[string]any, free string) *Result {
    out, errRes := rc.exec("hostname")     // runctx 快捷执行：自动带 env/become
    if errRes != nil {                     // 传输层失败（连不上等）
        return errRes
    }
    return &Result{Stdout: out.Stdout, Rc: out.Code, Changed: false,
        Failed: out.Code != 0, Msg: out.Stdout}
}

func init() { Register(&HostnameModule{}) }
```

2. playbook 里 `- hostname: {}` 即可用；
3. 更省事的替代：**不写 Go**，用 chart 脚本模块（§6.7）。

改完跑：`go build ./... && go vet ./... && go test ./...`，再
`golangci-lint run ./...`（CI 同款）。
