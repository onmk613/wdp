# 06 部署策略与自动回滚

`strategy` 是 play 级配置：控制分批节奏、批间健康门、失败自动回滚。不配置 strategy 时维持传统 `serial` 语义（批次失败不阻断后续批次）。

## 三种策略类型

```yaml
- name: 分批发布
  hosts: webservers
  strategy:
    type: canary          # linear | rolling | canary
    batch: "10%"          # 每批主机数："10%" 百分比 或 "3" 绝对数（缺省 25%）
    gate:                 # 健康门（可选）
      shell: 'curl -sf http://localhost:8080/health'
      until: '{{ if eq .result.rc 0 }}ok{{ end }}'   # 缺省即 rc==0
      retries: 10
      delay: 3
    auto_rollback: true   # 批次失败或门未过 → 回滚该批变更（可选）
  tasks: …
```

| type | 行为 |
|---|---|
| `rolling` | 按 batch 尺寸顺序分批 |
| `canary` | 首批固定 1 台金丝雀，其余按 batch 分批 |
| `linear` | 显式声明传统语义（等价不配 strategy，按 serial 分批） |

`batch` 缺省 25%（总主机 < 4 时一批到位）；百分比向上取整、min 1。

## 健康门（gate）

每批执行完**全部任务 + handlers flush 之后**运行健康检查：

- `shell`（必需）：健康检查命令
- `until`：判定条件（缺省 `rc == 0`）
- `retries` / `delay`：重试次数（缺省 3）与间隔秒

任何主机门未通过 → 该批判定失败 → **终止后续批次**（`auto_rollback: true` 时先回滚该批）。

## 失败传播

- **配置 strategy 后**：批次任务失败或门未通过 → 终止后续批次（防错误扩大）
- **未配置 strategy**（纯 serial）：批次失败不阻断后续批次（Ansible 传统语义）

## 自动回滚（auto_rollback）

批次失败或门未通过时，按该批各主机的**变更日志逆序**回滚：

| 模块 | 回滚动作 |
|---|---|
| `copy` / `template` | 覆盖前快照恢复；新建文件删除 |
| `file` | 新建（directory/touch/link）删除；修改/删除/属性变更快照恢复 |
| `unarchive` | 新建的目标目录删除 |

**无法自动回滚**（过程性变更，执行前评估报告会明确提示）：

- `shell` / `command` / `script`：自行在 rescue 或应用层处理
- `package` / `service` / `user` / `group`：逆操作请写入 `uninstall.yaml`
- `get_url` / `lineinfile` 之外的远端副作用

要点：

- 快照目录在目标机 `/tmp/.wdp-rollback-<纳秒>`，play 正常结束后**自动清理**（不残留）
- 快照失败不阻塞部署（该文件将无法自动回滚，仅在结果中体现）
- 回滚动作以 `auto-rollback` 任务形式出现在输出与统计中
- 父 play 的策略对子 chart 任务生效（变更日志贯通）

## 可逆性评估（部署前确认）

chart 部署前自动统计任务可逆性并报告：

```
==> 应用包评估 [myapp 0.2.0]: 可逆 12（copy/template/file）· 只读 3 · 不可逆 5，如: shell/package/service；支持卸载（uninstall.yaml）…
```

存在不可逆操作时：交互终端逐次确认（回车=继续）；非 TTY 打印警告放行（CI 不挂起）；`--yes / -y` 跳过。

## 完整示例：金丝雀 + 门 + 回滚

```yaml
- name: 灰度发布
  hosts: webservers
  strategy:
    type: canary
    batch: "25%"
    gate:
      shell: 'curl -sf http://localhost:8080/health || systemctl is-active myapp'
      retries: 10
      delay: 3
    auto_rollback: true
  tasks:
    - name: 下发新版本
      copy:
        src: files/myapp-1.2.3.tar.gz
        dest: /opt/myapp/app.tar.gz
      notify: 重启服务
  handlers:
    - name: 重启服务
      systemd_unit:
        name: myapp.service
        state: restarted
```

执行节奏：第 1 台金丝雀 → 门检查 → 通过则按 25% 分批推进；任一批失败回滚该批文件类变更并停止。

`wdp new myapp --full` 生成的骨架包含本模式的可直接运行版本（check 模式零风险演练）。
